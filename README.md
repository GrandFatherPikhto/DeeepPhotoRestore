# Непрерывная модель обучения PyTorch

## Что уже есть?
* Базовое сохранение/загрузка весов (state_dict).
* Сохранение стандартного чекпоинта (эпоха, оптимизатор, лосс).
* Нюансы переноса между CPU и GPU и важность .eval() / .train().
* Продвинутый шаблон с перехватом Ctrl+C (KeyboardInterrupt) и точечным возобновлением с конкретного батча.

Скрипт сделан для сохранения процесса обучения и последующего восстановления модели в PyTorch используются функции torch.save() и torch.load(). Существует два основных подхода: сохранение только весов (рекомендуемый способ) и сохранение состояния всей контрольной точки (checkpoint) для продолжения прерванного обучения.
------------------------------
## 1. Сохранение и восстановление только весов (Рекомендуется)
Этот способ сохраняет только параметры модели (состояние state_dict), что делает файлы компактными. Для восстановления вам потребуется сначала создать экземпляр класса модели в коде.
## Сохранение весов

import torch
# ... код создания и обучения вашей модели ...# torch.save(model.state_dict(), 'путь_к_файлу.pth')
torch.save(model.state_dict(), 'model_weights.pth')

## Восстановление весов

# 1. Создаем точно такую же структуру моделиmodel = MyModelClass() 
# 2. Загружаем сохраненный словарь параметровweights = torch.load('model_weights.pth', map_location=torch.device('cpu'))
# 3. Загружаем веса непосредственно в модель
model.load_state_dict(weights)
# 4. Переводим в режим оценки (если планируется инференс, а не обучение)
model.eval()

------------------------------
## 2. Сохранение чекпоинта (Для возобновления обучения)
Если обучение идет долго и может прерваться, необходимо сохранять не только веса модели, но и состояние оптимизатора, номер текущей эпохи и лосс.
## Сохранение чекпоинта

checkpoint = {
    'epoch': epoch,
    'model_state_dict': model.state_dict(),
    'optimizer_state_dict': optimizer.state_dict(),
    'loss': loss,
}
torch.save(checkpoint, 'checkpoint.pth')

## Восстановление чекпоинта для продолжения обучения

# 1. Инициализируем модель и оптимизаторmodel = MyModelClass()optimizer = torch.optim.Adam(model.parameters(), lr=0.001)
# 2. Загружаем чекпоинтcheckpoint = torch.load('checkpoint.pth')
# 3. Восстанавливаем состояния
model.load_state_dict(checkpoint['model_state_dict'])
optimizer.load_state_dict(checkpoint['optimizer_state_dict'])start_epoch = checkpoint['epoch'] + 1loss = checkpoint['loss']
# 4. Переводим в режим обучения
model.train()

------------------------------
## Важные нюансы при переносе устройств

* С GPU на CPU: Если вы обучали модель на видеокарте, а восстанавливаете на процессоре, обязательно укажите map_location:

torch.load('model.pth', map_location=torch.device('cpu'))

* С CPU на GPU:

device = torch.device("cuda")
model.load_state_dict(torch.load('model.pth', map_location="cuda:0"))
model.to(device)

* Метод model.eval(): После загрузки весов для тестирования или использования (инференса) вызов model.eval() обязателен. Он отключает слои Dropout и BatchNorm, иначе результаты предсказаний будут некорректными.

Да, это абсолютно возможно. PyTorch без проблем продолжит обучение ровно с того батча и эпохи, на которых его прервали, если правильно обработать сигнал Ctrl+C (в Python это исключение KeyboardInterrupt) и корректно сохранить состояние.
Когда вы нажимаете Ctrl+C, Python прерывает выполнение кода. Если вы не перехватили это событие, программа просто завершается, и все данные из оперативной памяти стираются.
Чтобы модель «захотела» продолжить, нужно сделать две вещи: автоматически сохранять чекпоинт при прерывании и правильно инициализировать загрузчик данных (DataLoader) при перезапуске.
Вот готовый шаблон, как это реализуется на практике:
## 1. Код обучения с перехватом Ctrl+C
Оберните ваш цикл обучения в блок try...except KeyboardInterrupt. Это позволит при нажатии Ctrl+C не вылетать с ошибкой, а сначала аккуратно сохранить всё состояние на диск.

import torch
# Инициализация модели, оптимизатора, датасетаmodel = MyModelClass()optimizer = torch.optim.Adam(model.parameters(), lr=0.001)# ... ваш train_loader ...
start_epoch = 0start_batch_idx = 0
# --- БЛОК ВОССТАНОВЛЕНИЯ (если файл существует) ---import oscheckpoint_path = 'resume_checkpoint.pth'
if os.path.exists(checkpoint_path):

    checkpoint = torch.load(checkpoint_path)
    
    model.load_state_dict(checkpoint['model_state_dict'])
    optimizer.load_state_dict(checkpoint['optimizer_state_dict'])
    start_epoch = checkpoint['epoch']
    # Прибавляем 1 к батчу, чтобы не повторять тот, на котором прервались
    start_batch_idx = checkpoint['batch_idx'] + 1 
    print(f"Продолжаем с Эпохи: {start_epoch}, Батча: {start_batch_idx}")
# --- ОСНОВНОЙ ЦИКЛ ОБУЧЕНИЯ ---try:

            loss = criterion(output, target)
            loss.backward()
            optimizer.step()

        'epoch': epoch,

## Главные секреты, почему это обычно не работает (и как починить):

   1. Забывают про индекс батча (batch_idx): Если сохранять только номер эпохи, то при прерывании в середине эпохи (например, на 5000-м батче из 10000) вам придется начинать всю эпоху заново. Код выше сохраняет конкретный батч и пропускает уже пройденные с помощью continue.
   2. Случайные числа (Random Seed): Если внутри модели или датасета используется сильный фактор случайности (например, аугментация «на лету»), для идеальной точности нужно также сохранять и восстанавливать состояние генератора случайных чисел PyTorch:
   * Сохранение: 'rng_state': torch.get_rng_state()
      * Восстановление: torch.set_rng_state(checkpoint['rng_state'])
   3. Состояние Оптимизатора: Оптимизаторы вроде Adam хранят в себе моменты (историю градиентов) для каждого веса. Если их не сохранить и не загрузить через optimizer.load_state_dict(), то после перезапуска модель совершит хаотично большой шаг и может испортить уже обученные веса.

* Используете ли вы shuffle=True (перемешивание) в вашем DataLoader? (При перемешивании пропуск батчей через continue может работать неидеально, и для жесткой точности требуется кастомный Sampler).

## Подготовка

Отличная идея. При частых экспериментах папки быстро забиваются старыми данными, и автоматическая очистка — это лучшее средство от хаоса на диске.
Давайте добавим этот функционал прямо в prepare_dataset.py в виде нового аргумента командной строки --clean.
## Как это будет работать:

   1. При запуске python prepare_dataset.py -opt ... --clean скрипт проверит наличие старых папок.
   2. Он полностью очистит папку препаренного датасета (datasets/jpeg_fcn), чтобы новые картинки не смешивались со старыми.
   3. Он проверит папку обучения (experiments/JPEG-FCN-Resnet-50). Если она существует, скрипт не удалит её безвозвратно, а сделает безопасный архивный бэкап в формате .zip (с указанием даты и времени) и только после этого очистит её для нового старта.

* Обычный запуск (без очистки):

------------------------------
## 🔍 Анализ графиков: почему мы вышли на «полочку»?## 1. Идеальная сходимость (График Loss)
Кривая потерь Train Loss упала практически в ноль и превратилась в идеальную прямую линию уже к 50-му глобальному шагу. Это говорит о том, что выбранный шаг обучения lr: 1e-3 и оптимизатор AdamW сработали безупречно. Модель не штормило, не было расходимости (вылетов градиентов), она мгновенно нашла локальный минимум.
## 2. Физический предел деградации jpeg_quality: 15
Посмотрите на график PSNR: модель стартовала с отрицательных значений (глубокий шум и каша), затем совершила мощный рывок вверх и намертво зафиксировалась на отметке чуть выше 20 dB.
Эта «полочка» возникла потому, что при качестве 15 алгоритм JPEG стирает из картинки высокочастотную информацию (текстуры, мелкие волоски, поры) физически и безвозвратно. Архитектура модели (в данном случае проверочная FCN-Resnet) восстановила всё, что можно было восстановить математически (крупные контуры, цвета, общие формы). Дальше ей просто не за что цепляться в пикселях — достигнут теоретический предел для данного типа деградации.
## 3. Эффект микро-датасета
Поскольку глобальный шаг (Global Step) на графике дошел ровно до 500 при 500 эпохах, это окончательно подтверждает наше предположение: в одной эпохе у вас ровно 1 шаг (батч).

* Модель выучила эти несколько картинок наизусть за первые 50 шагов.
* Остальные 450 шагов она просто удерживала этот идеальный для неё результат, поэтому «полочка» получилась такой невероятно ровной, без единого колебания.

## 🛠️ Как в следующем эксперименте пробить эту полочку и уйти на 25-30+ dB?
Теперь, когда вся система автоматизации, очистки, бэкапов и графиков работает как швейцарские часы, вы можете двигаться дальше. Чтобы поднять качество реставрации, сделайте следующее:

   1. Накормите модель данными: Положите в jpeg_images хотя бы 50–100 качественных изображений и запустите prepare_dataset.py -opt ... --clean. На графике по оси X вы увидите уже не 500 шагов, а десятки тысяч, и кривая PSNR станет живой.
   2. Смягчите условия JPEG: Поставьте в YAML jpeg_quality: 40. Артефактов станет меньше, полезной информации в файлах останется больше, и модель сможет вытянуть PSNR гораздо выше.
   3. Переключитесь на тяжелую артиллерию: Замените в YAML проверочную сеть на оригинальную архитектуру NAFNet (с прописанным путем к arch_file), параметры которой мы настраивали в model_loader.py. За счет блоков нелинейной фильтрации без активаций она способна творить чудеса с JPEG-сеткой.
