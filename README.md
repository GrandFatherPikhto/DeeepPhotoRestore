# DeepPhotoRestore – Восстановление RAW‑изображений на основе NAFNet

**DeepPhotoRestore** – программный комплекс для совместной демозаики и суперразрешения (Joint Demosaicing and Super‑Resolution, JDSR) изображений, полученных с матрицей Байера (RGGB). Проект реализует сквозной конвейер: от физически корректной генерации синтетических пар (LQ – упакованный RAW, HQ – резкое RGB) до обучения глубокой нейросетевой модели на базе адаптированной архитектуры NAFNet с частотной функцией потерь (Focal Frequency Loss).

---

## 📌 Возможности

- **Генерация датасета** с моделированием реального тракта: оптическое уменьшение (`downscale_factor`), PSF‑размытие, маска Байера, коррелированный/некоррелированный шум.
- **Адаптированная модель NAFNet** с поддержкой 4‑канального входа (RGGB) и масштабированием через `PixelShuffle` **после** сети (работа в низком разрешении → высокая скорость и экономия VRAM).
- **Комбинированная функция потерь**: L1 + Focal Frequency Loss (линейная или логарифмическая) с программируемым прогревом.
- **Полный цикл обучения** с автоматическим возобновлением (в т.ч. аварийным), клиппингом градиентов, валидацией (PSNR, SSIM) и логированием (CSV, TensorBoard).
- **Бенчмаркинг**: сравнение с классическими методами демозаики (билинейная, Malvar‑He‑Cutler).
- **Инференс на видео** (опционально).
- **Визуализация метрик** через скрипт построения графиков.

## 🚀 Быстрый старт

### 1. Установка зависимостей

```bash
pip install torch torchvision basicsr opencv-python scikit-image tifffile pillow matplotlib pandas pyyaml tqdm albumentations scipy imageio
```

### 2. Подготовка исходных изображений

Поместите резкие RGB‑изображения (можно NEF, CR2, PNG, JPG) в папку, указанную в конфиге как `source_images_dir`. По умолчанию это `source_images/`.

### 3. Настройка конфигурации

Скопируйте пример конфига (например, `configs/RAW_NAFNet_Final_100.yml`) и отредактируйте пути, параметры деградации и обучения.  

**Важное соотношение:**  
- `network_g.upscale_factor` должен быть равен `process_data.downscale_factor × 2`.
- `datasets.train.lq_size = datasets.train.gt_size // network_g.upscale_factor`.

### 4. Генерация датасета

```bash
python prepare_dataset.py -opt configs/your_config.yml --clean-dataset
```

Флаг `--clean-dataset` полностью пересоздаёт папки `train/` и `test/`. После генерации в `dataset_root/train/lq_inputs` появятся файлы `*_bayer.tiff`, в `hq_targets` – соответствующие `*.png`.

### 5. Запуск обучения

```bash
python run_training.py -opt configs/your_config.yml
```

- Обучение автоматически продолжится с последнего чекпоинта (если включён `auto_resume`).
- Первые `ffl_start_epoch` эпох используется только L1‑лосс, затем подключается FFL.
- Логи пишутся в `experiments/{name}/train_metrics.csv` и `val_metrics.csv`.
- Валидация (SSIM и PSNR) выполняется каждую эпоху (или с заданной частотой).

### 6. Оценка качества

```bash
# Baseline (билинейная и MHC демозаика)
python evaluate_baseline.py -opt configs/your_config.yml

# Построение графиков
python plot_metrics.py -opt configs/plot_metrics.yml
```

## 📅 2026-06-09 – Конвейер генерации визуальных отчётов (склейка пар с метриками)

### 1. Новый скрипт `generate_reports.py`
- **Модуль:** `generate_reports.py` (корневой скрипт)
- **Суть:** Автоматически создаёт YAML-конфиг со списком пар изображений (эпохи `start_epoch` vs `finish_epoch`, а также HQ vs LQ), затем запускает склейку каждой пары в отдельный файл.
- **Ключевые аргументы:**
  - `--image_size`, `--spacing`, `--background_color` (теперь поддерживается RGBA, например `0,0,0,0` для прозрачного фона)
  - `--border_disabled`, `--border_color`, `--border_thickness`
  - `--metrics_enabled`, `--metrics_list`, `--metrics_position`, `--metrics_color`
- **Результат:** Упрощён выпуск наглядных сравнительных таблиц для диссертации, каждая пара обрабатывается независимо.

### 2. Генератор конфигурации отчёта (`report_config.py`)
- **Модуль:** `libraries/report_config.py`
- **Суть:** Добавлены функции:
  - `get_dsc_numbers` – извлекает номера тестовых файлов из `test/lq_inputs`.
  - `get_epoch_paths` – формирует пути к предсказаниям для заданной эпохи.
  - `get_lq_paths` / `get_hq_paths` – пути к LQ-превью и эталонам.
  - `generate_report_yaml` – создаёт YAML-файл со списком пар и глобальными настройками (размер, отступ, рамка, метрики).
- **Результат:** Отделение логики генерации YAML от склейки, повышение модульности.

### 3. Склейка с метриками (`report_generator.py`)
- **Модуль:** `libraries/report_generator.py`
- **Суть:** Функция `process_pair`:
  - Загружает два изображения, масштабирует с сохранением пропорций до `image_size`, добавляет рамку (если включена).
  - Поддерживает RGBA: если фон прозрачный или изображение имеет альфа-канал, итоговое полотно создаётся в режиме `RGBA`, вставка с маской.
  - Вычисляет метрики (`compute_metrics`): PSNR и SSIM между финишной эпохой и эталоном HQ (только для пар, чей путь содержит `epochs`).
  - Накладывает текст метрик на склеенное изображение (`draw_text_on_image`) с полупрозрачной подложкой и настраиваемым положением.
- **Результат:** Автоматическая количественная оценка качества на визуальных сравнениях, без ручного расчёта.

### 4. Генерация LQ-превью (`lq_generator.py`)
- **Модуль:** `libraries/lq_generator.py`
- **Суть:** Функция `generate_previews_from_config` проверяет наличие PNG-превью в `experiment_dir/lq_preview/`. Если их нет, берёт 4-канальные TIFF из `test/lq_inputs/`, применяет билинейную демозаику (`bilinear_demosaic_rggb`) и сохраняет PNG.
- **Зачем:** Устранить зависимость от внешних инструментов и ускорить повторные запуски (кеширование).
- **Результат:** Скрипт отчёта стал самодостаточным – не требует предварительной ручной генерации превью.

### 5. Исправление ошибки `bad transparency mask`
- **Модуль:** `libraries/report_generator.py`
- **Суть:** В `process_pair` добавлена функция `ensure_rgba`, которая преобразует RGB-изображения в RGBA с непрозрачным альфа-каналом, если требуется смешивание. Вставка выполняется с маской только в режиме RGBA.
- **Результат:** Больше нет вылетов при использовании прозрачного фона или изображений с разной глубиной цвета.

### 6. Автоматическое создание родительских папок
- **Модули:** `generate_reports.py`, `report_generator.py`
- **Суть:** Перед записью выходного файла выполняется `Path(output_path).parent.mkdir(parents=True, exist_ok=True)`.
- **Результат:** Исключены ошибки `FileNotFoundError` при сохранении во вложенные несуществующие директории.

### 7. Shebang и кодировка
- **Модули:** `generate_reports.py`, `lq_generator.py`, `report_generator.py`
- **Суть:** Добавлены строки `#!/usr/bin/env python` (или `#!.venv/bin/python`) и `# -*- coding: utf-8 -*-`.
- **Результат:** Упрощён запуск в Unix-подобных системах и обеспечена совместимость с Python 2 (хотя проект на Python 3).

## 📊 Генерация визуальных отчётов

После обучения модели можно создать наглядные сравнения (side‑by‑side) для выбранных эпох и исходных пар:

```bash
./generate_reports.py -opt configs/your_config.yml --finish_epoch 3890
```

Скрипт автоматически:
- Находит все тестовые файлы.
- Генерирует LQ-превью (если отсутствуют).
- Склеивает пары `epoch_start vs epoch_finish` и `HQ vs LQ`.
- Для пар эпох вычисляет PSNR и SSIM и накладывает их на изображение.
- Поддерживает прозрачный фон, рамки, настройку шрифта.

Подробнее см. [REPORT.md](docs/REPORT.md).
