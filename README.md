# DeepPhotoRestore: Pipeline для повышения качества изображений с CFA-сенсоров

## 1. Что это такое?

DeepPhotoRestore — исследовательский проект, реализующий полный цикл повышения качества изображений, полученных с малогабаритных сенсоров, оснащённых мозаичными светофильтрами (CFA). В основе подхода лежит глубокое обучение: нейросетевая архитектура NAFNet (Nonlinear Activation Free Network) обучается восстанавливать полноцветное RGB-изображение из зашумлённой мозаики (сигнал типа RGGB), имитирующей физический тракт реальной камеры.

### Основные решаемые задачи

- **Физически достоверная генерация обучающих пар (LQ / HQ):**  
  Эталонные изображения высокого качества (HQ) проходят через модель деградации (пространственное сжатие, свёртка с функцией рассеяния точки (PSF, ЧКХ), наложение маски Байера, добавление коррелированного шума). На выходе получается Low Quality (LQ) сигнал — 4-канальный массив (R, G₁, G₂, B) в 16-битном TIFF.
- **Обучение NAFNet с комбинированной пространственно-частотной функцией потерь:**  
  Совместная демозаика и шумоподавление. Используется L1Loss + FocalFrequencyLoss (FFL), что позволяет восстанавливать высокочастотные детали и подавлять муар.
- **Оценка качества:**  
  Вычисляются PSNR, SSIM на тестовой выборке, сохраняются восстановленные изображения. Результаты логируются в файлы и TensorBoard.
- **Сравнение с классическими методами:**  
  Билинейная интерполяция и (опционально) градиентная демозаика (MHC) служат baseline.

## 2. `run_pipeline.py` — предобученческий конвейер

### Назначение
Скрипт проверяет существование и при необходимости генерирует обучающий датасет, выполняет визуальный контроль и smoke-тест градиентов нейросети.

### Действия
1. Парсит аргументы командной строки и загружает конфигурационный YAML-файл.
2. При запросе (`--clean-dataset`) удаляет папки `train/` и `test/` внутри `dataset_root`, затем запускает генерацию пар LQ/HQ (через модули `pipeline_generation_*`).
3. Загружает датасет через `RestorationDataset` и сохраняет примеры LQ и HQ в папку визуализации (с использованием билинейной демозаики для 4-канальных LQ).
4. Создаёт модель NAFNet и выполняет один шаг оптимизации (smoke‑test) для проверки градиентов и совместимости с GPU.

### Формат конфигурационного файла (используемые секции)

| Секция | Ключи | Назначение |
|--------|-------|-------------|
| `path` | `source_images_dir`, `dataset_root` | Путь к исходным HQ-изображениям и корень сгенерированного датасета |
| `process_data` | `downscale_factor`, `noise` (snr_db, correlated, psf_sigma) | Параметры физической деградации |
| `network_g` | `num_in_ch`, `num_out_ch`, `width`, `middle_blk_num`, `enc_blk_nums`, `dec_blk_nums` | Архитектура NAFNet |
| `datasets.train` | `batch_size_per_gpu`, `num_worker_per_gpu` | Настройки загрузчика данных (используются в датасете) |
| `visuals_logger` | `output_dir`, `lq_preview_name`, `gt_reference_name` | Папка и имена файлов для визуального контроля |
| `pipeline_logger` | `log_file` | Путь к общему логу конвейера |

### Ключи командной строки

- `-opt PATH` — обязательный, путь к YAML-конфигу.
- `--clean-dataset` — удалить папки `train/` и `test/` перед генерацией.
- `--clean-visuals` — удалить старые файлы визуализации (`samples/debug_visuals/`).
- `--clean` (устаревший) — включает оба флага выше.

### Где сохраняются файлы

- **Датасет:** `dataset_root/train/` и `dataset_root/test/` (LQ — 4-канальные TIFF, HQ — PNG).
- **Визуальный контроль:** `samples/debug_visuals/debug_lq_preview.png`, `debug_gt_reference.png`.
- **Общий лог:** `samples/debug_pipeline/pipeline.log`.

## 3. `run_training.py` — обучение нейросети

### Назначение
Запускает обучение модели NAFNet на сгенерированном датасете с комбинированной функцией потерь (L1 + FFL), сохраняет чекпоинты, логирует метрики, выполняет валидацию.

### Действия
1. Загружает конфиг, инициализирует устройство (GPU/CPU), при флаге `--clean-training` очищает папку эксперимента.
2. Создаёт датасет и DataLoader (с аугментациями: повороты на 90°, отражения).
3. Инициализирует NAFNet, оптимизатор AdamW, планировщик CosineAnnealingLR.
4. В цикле по эпохам выполняет прямой и обратный проход, обновляет веса.
5. Каждую эпоху (или с заданной частотой) запускает валидатор, который вычисляет PSNR и SSIM на тестовых изображениях, сохраняет восстановленные картинки.
6. Периодически сохраняет чекпоинты (состояние модели, оптимизатора, планировщика).

### Формат конфигурационного файла (используемые секции)

| Секция | Ключи | Назначение |
|--------|-------|-------------|
| `name` | — | Имя эксперимента (папка в `experiments/`) |
| `path` | `dataset_root`, `resume_path` | Корень датасета, путь для чекпоинтов |
| `datasets.train` | `batch_size_per_gpu`, `num_worker_per_gpu`, `auto_resume`, `gt_size` | Настройки DataLoader и размер патча |
| `network_g` | (те же, что в pipeline) | Архитектура сети |
| `train` | `num_epochs`, `optim_g`, `scheduler`, `validation_freq`, `save_checkpoint_epoch` | Гиперпараметры обучения и частота валидации/сохранения |
| `logger` | `use_tb_logger`, `print_freq`, `log_file_name`, `file_log_freq`, `include_in_console`, `include_in_file_log` | Настройки логирования (см. раздел 4) |
| `losses` | `l1_weight`, `ffl_weight`, `ffl_alpha` | Веса компонентов комбинированной потери |
| `visuals_logger` | (используется в валидаторе) | Необязательно |
| `pipeline_logger` | `log_file` | Общий лог (для валидатора) |

### Ключи командной строки

- `-opt PATH` — обязательный, путь к YAML.
- `--clean-training` — удалить папку эксперимента (`experiments/EXP_NAME`) перед запуском.
- `--resume PATH` — возобновить обучение из указанного чекпоинта (переопределяет путь в конфиге).

### Где сохраняются результаты

- **Чекпоинты:** по пути `resume_path` (обычно `checkpoints/resume_nef_nafnet.pth`).
- **Логи метрик (текстовый):** `experiments/EXP_NAME/train_progress.log`.
- **Логи метрик (CSV):** `experiments/EXP_NAME/train_metrics.csv` (при `log_csv: true`).
- **TensorBoard:** `experiments/EXP_NAME/tb_logs/`.
- **Валидационные изображения:** `experiments/EXP_NAME/val_predictions/epoch_*_*.png`.
- **Общий лог (pipeline.log):** `samples/debug_pipeline/pipeline.log` (туда пишутся сообщения валидатора, SSIM и пр.).

## 4. Логирование

Система логирования разделена на два канала:

- **`pipeline_logger`** — единый логгер для всего проекта (используется в `run_pipeline`, `run_training`, `training_validator`, `evaluate_baseline`). Настраивается в секции `pipeline_logger` YAML (ключ `log_file`). Пишет в файл и в консоль (с временными метками).
- **`TrainingLogger`** — специализированный логгер для метрик обучения. Настраивается в секции `logger` YAML.

### Какие характеристики можно сохранять

- **В текстовый файл (`train_progress.log`)** — управляется через `include_in_file_log`:
  - loss, psnr, learning_rate, delta_psnr, grad_variance, tv_ratio, vram_usage, log_ssim.
- **В консоль** — управляется через `include_in_console`:
  - loss, psnr, vram (и, опционально, learning_rate).
- **В CSV** (`train_metrics.csv`) — все перечисленные метрики плюс шаг итерации.
- **В TensorBoard** — loss, psnr, learning_rate.

### Зачем нужны эти метрики

| Метрика | Смысл |
|---------|-------|
| Loss | Основной показатель сходимости (L1 + FFL). |
| PSNR | Пиковое отношение сигнал/шум (чем выше, тем лучше). |
| SSIM | Структурное сходство (оценивает восприятие). |
| LR | Скорость обучения (мониторинг расписания). |
| ΔPSNR | Изменение PSNR между шагами (раннее остановка). |
| GradVar | Дисперсия градиентов (признак затухания). |
| TV ratio | Отношение вариаций предсказания и эталона (контроль «мыла»). |
| VRAM | Использование памяти GPU (для оптимизации батча). |

## 5. `plot_metrics.py` — конфигурируемый графопостроитель

### Назначение
Построение нескольких типов графиков на основе CSV-логов и текстовых логов (pipeline.log). Конфигурация задаётся в отдельном YAML-файле, что позволяет легко создавать иллюстрации для диссертации.

### Откуда берёт данные
- CSV-файлы с метриками (например, `train_metrics.csv`).
- Текстовые логи (например, `pipeline.log`) — с помощью регулярных выражений извлекаются числовые значения (например, SSIM).

### Формат конфигурационного файла (пример)

```yaml
experiment_dir: "experiments/RAW-NAFNet-D600"
output_dir: "experiments/RAW-NAFNet-D600/figures"
data_files:
  train_metrics: "experiments/RAW-NAFNet-D600/train_metrics.csv"
  pipeline_log: "samples/debug_pipeline/pipeline.log"

baseline:
  psnr: 34.61
  ssim: 0.9640
  label: "Bilinear"

plots:
  - type: line
    title: "Кривая потерь (Loss)"
    data:
      source: csv
      file_ref: train_metrics
      x: step
      y: loss
    smoothing: 0.9
    y_label: "Loss"
    save: loss_curve.png

  - type: comparison
    title: "Сравнение PSNR: NAFNet vs Bilinear"
    data:
      source: csv
      file_ref: train_metrics
      x: step
      y: psnr
    baseline_value: 34.61
    baseline_label: "Bilinear"
    y_label: "PSNR (dB)"
    save: psnr_comparison.png

  - type: line
    title: "SSIM на валидации"
    data:
      source: log
      file_ref: pipeline_log
      pattern: "SSIM = (\\d+\\.\\d+)"
    smoothing: 1
    y_lim: [0.5, 1.0]
    y_label: "SSIM"
    save: ssim_curve.png
```

### Типы графиков
- `line` — обычный линейный график.
- `comparison` — линия + горизонтальная прямая (baseline).
- `multi_line` — несколько линий на одном поле.

### Запуск
```bash
./plot_metrics.py -opt options/plot/RAW_NAFNet_NikonD600.yml
```
Графики сохраняются в `output_dir` в формате PNG (300 dpi).

## 7. `evaluate_baseline.py` — сравнение с классическими методами демозаики

### Назначение
Скрипт вычисляет объективные метрики (PSNR, SSIM) для классических алгоритмов демозаики, не использующих нейросети. Результаты служат эталоном (baseline) для сравнения с обученной моделью NAFNet.

### Что реализовано
- **Билинейная интерполяция** (обязательно) — каждый из 4 каналов (R, G1, G2, B) увеличивается в 2 раза билинейной интерполяцией, зелёные усредняются, формируется RGB.
- **Градиентный метод Malvar–He–Cutler (MHC)** — опционально; в текущей версии используется заглушка (билинейная), поскольку полная реализация требует дополнительных усилий.

### Откуда берёт данные
- Тестовые LQ-файлы (4-канальные TIFF) из папки `dataset_root/test/lq_inputs/`.
- Эталонные HQ-изображения (PNG) из папки `dataset_root/test/hq_targets/`.

### Формат конфигурационного файла
Используется общий конфиг (тот же, что для `run_pipeline` и `run_training`). Скрипт считывает:
- `dataset_root` (из секции `path`) — корень датасета.
- Параметры генерации LQ не используются, так как демозаика применяется к уже готовым файлам.

### Запуск
```bash
./evaluate_baseline.py -opt options/train/RAW_NAFNet_NikonD600.yml
```

### Что выводит
- Для каждого тестового файла — значения PSNR и SSIM для билинейной и (при наличии) MHC демозаики.
- В конце — средние значения по всей тестовой выборке.
- Все сообщения направляются в единый `pipeline_logger` (консоль и файл `samples/debug_pipeline/pipeline.log`).

### Пример вывода в логе
```
[INFO] DSC_0413: Bilinear PSNR=34.61 SSIM=0.9640 | MHC PSNR=34.61 SSIM=0.9640
[INFO] === BASELINE SUMMARY ===
[INFO] Bilinear  -> Mean PSNR = 34.61 dB, Mean SSIM = 0.9640
[INFO] MHC       -> Mean PSNR = 34.61 dB, Mean SSIM = 0.9640
```

### Назначение результатов
Эти числа (особенно билинейный baseline) используются для оценки эффективности нейросети: если NAFNet достигает более высоких PSNR/SSIM, то предложенный метод превосходит классику. В диссертации обычно приводят таблицу сравнения.

## 9. `inference.py` — восстановление изображений обученной моделью

### Назначение
Скрипт загружает обученную модель NAFNet и применяет её к произвольному входному изображению. Поддерживает два режима:
- **Восстановление готового LQ-файла** (4-канальный TIFF, сгенерированный `prepare_dataset`).
- **Полный цикл «испортить → восстановить»** для обычного RGB-изображения (JPEG, PNG). В этом случае скрипт самостоятельно применяет ту же цепочку деградации (сжатие, размытие, маска Байера, коррелированный шум), что и при обучении, а затем восстанавливает результат.

### Как использовать

#### 1. Восстановление существующего LQ-файла
```bash
./inference.py -opt options/train/RAW_NAFNet_NikonD600.yml \
               --input datasets/nef_nafnet/test/lq_inputs/DSC_0413_bayer.tiff \
               --output restored.png
```

#### 2. «Испортить» и восстановить произвольное RGB-изображение
```bash
./inference.py -opt options/train/RAW_NAFNet_NikonD600.yml \
               --input my_photo.jpg \
               --output restored_my_photo.png
```

#### 3. Явное указание чекпоинта (если он лежит не в стандартном месте)
```bash
./inference.py -opt options/train/RAW_NAFNet_NikonD600.yml \
               --input my_photo.jpg \
               --output restored.png \
               --checkpoint checkpoints/my_best_model.pth
```

### Параметры командной строки

| Аргумент | Обязательный | Описание |
|----------|--------------|----------|
| `-opt` | Да | Путь к YAML-конфигу (используются секции `path`, `network_g`, `process_data`, `datasets.train.gt_size`, `pipeline_logger`) |
| `--input` | Да | Путь к входному файлу (4-канальный TIFF или обычное RGB-изображение) |
| `--output` | Нет (по умолчанию `restored.png`) | Путь для сохранения восстановленного изображения (PNG) |
| `--checkpoint` | Нет | Путь к файлу чекпоинта модели. Если не указан, берётся из `path.resume_path` конфига |

### Что происходит внутри

1. **Загрузка модели:** создаётся экземпляр NAFNet с параметрами из `network_g`, веса загружаются из чекпоинта.
2. **Автоопределение типа входного файла:**
   - Если файл — 4-канальный TIFF (обычно созданный `prepare_dataset`), он интерпретируется как LQ и подаётся на вход модели напрямую.
   - Иначе файл читается как RGB, и к нему применяется полная цепочка деградации, заданная в секции `process_data` конфига (downscale, PSF, маска Байера, шум). Полученный LQ затем восстанавливается моделью.
3. **Восстановление:** прямой проход через модель с последующим сохранением результата в PNG.
4. **Опциональный расчёт метрик:** если входной файл был RGB и произошла деградация, скрипт вычисляет PSNR и SSIM между восстановленным изображением и промежуточным HQ (до наложения шума и мозаики). Это позволяет оценить качество восстановления в синтетическом эксперименте.

### Зависимости
- Установленные библиотеки: `torch`, `tifffile`, `numpy`, `Pillow`, `scikit-image` (для расчёта PSNR/SSIM).
- Модель должна быть обучена с теми же параметрами деградации (`process_data`), которые указаны в конфиге. Иначе результат может быть неудовлетворительным.

### Пример вывода (консоль)
```
[INFO] Устройство: cuda
[INFO] Модель загружена из checkpoints/resume_nef_nafnet.pth
[INFO] Результат сохранён в restored.png
[INFO] PSNR = 28.34 dB, SSIM = 0.9123
```

### Примечания
- Входное RGB-изображение не обязательно должно быть того же размера, что и обучающие патчи (256×256). Скрипт автоматически изменяет размер до `gt_size` перед подачей в модель.
- Для более реалистичного «порчи» рекомендуется использовать исходные изображения высокого качества (без артефактов сжатия). Скрипт сам уменьшит разрешение согласно `downscale_factor`.

## 8. Выводы

Разработанный программный комплекс DeepPhotoRestore полностью реализует заявленную цель диссертации:

- Создана **физически достоверная модель деградации** изображений малогабаритным CFA-сенсором, включающая пространственное сжатие, ЧКХ-размытие, мозаику Байера и коррелированный шум.
- Реализовано **обучение нейросети NAFNet** с комбинированной пространственно-частотной функцией потерь (L1 + FFL), позволяющей восстанавливать высокочастотные детали и подавлять муар.
- Обеспечена **полная конфигурируемость** всех этапов через YAML-файлы (генерация датасета, архитектура сети, гиперпараметры, логирование).
- Разработана **модульная структура** (каждая библиотека ≤100 строк), что упрощает поддержку и расширение.
- Внедрена **централизованная система логирования** с выводом метрик в консоль, файлы (текстовые и CSV) и TensorBoard.

## Метод Б. Скрипт комплексного тестирования и бенчмаркинга

Для детального анализа конфигурации и оценки производительности графического процессора при выполнении матричных операций создайте файл test_cuda.py.

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
# """Скрипт верификации системных параметров PyTorch и бенчмаркинга GPU."""
#
import sysimport timeimport torch
def run_benchmark():
    print("=" * 50)
    print(" СИСТЕМНАЯ ИНФОРМАЦИЯ ".center(50, "="))
    print("=" * 50)
    print(f"Версия Python:       {sys.version.split()[0]}")
    print(f"Версия PyTorch:      {torch.__version__}")

    cuda_available = torch.cuda.is_available()
    print(f"Доступность CUDA:    {'ВКЛЮЧЕНА' if cuda_available else 'ВЫКЛЮЧЕНА'}")

    if not cuda_available:
        print("\n[ОШИБКА]: Доступ к GPU отсутствует. Вычисления невозможны.")
        return

    device_properties = torch.cuda.get_device_properties(0)
    total_memory_gb = device_properties.total_memory / (1024 ** 3)
    
    print(f"Версия CUDA в Torch: {torch.version.cuda}")
    print(f"Имя устройства:      {torch.cuda.get_device_name(0)}")
    print(f"Память GPU (всего):  {total_memory_gb:.2f} GB")

    print("\n" + "=" * 50)
    print(" ТЕСТ ПРОИЗВОДИТЕЛЬНОСТИ ".center(50, "="))
    print("=" * 50)

    # Инициализация тензоров на графическом процессоре
    device = torch.device("cuda")
    x = torch.randn(10000, 10000, device=device, dtype=torch.float32)
    y = torch.randn(10000, 10000, device=device, dtype=torch.float32)

    # Предварительный запуск (Warm-up) для исключения времени на аллокацию памяти
    _ = torch.matmul(x, y)
    torch.cuda.synchronize()

    # Фиксация времени выполнения операции матричного умножения
    start_time = time.time()
    _ = torch.matmul(x, y)
    torch.cuda.synchronize()
    end_time = time.time()

    execution_time_ms = (end_time - start_time) * 1000
    print(f"Время выполнения операции (Мат. умножение): {execution_time_ms:.2f} мс")
    print("=" * 50)
if __name__ == "__main__":
    run_benchmark()
```

Запуск скрипта выполняется стандартной командой из терминала:

```bash
python3 test_cuda.py
```

Критерий успешного развертывания:

Возвращение значения True в строке доступности CUDA и успешное прохождение бенчмарка без генерации исключений (RuntimeError). Среда полностью готова к обучению и инференсу нейросетевых моделей реставрации изображений.

## 6.Интеграция архитектуры NAFNet и разрешение конфликтов среды вычислений

Включение сторонней архитектуры NAFNet (Nonlinear Activation Free Network) в состав комплексного проекта реставрации графики Photo-Restoration-PyTorch сопряжено с рядом критических инфраструктурных коллизий. Данный раздел документирует процесс развертывания субмодуля, анализ возникающих ошибок импорта и методологию их гарантированного устранения.

### Развертывание репозитория как Git-субмодуля
Для сохранения связи с апстрим-разработчиками и исключения дублирования стороннего исходного кода в основном дереве проекта, интеграция осуществляется через механизм Git-субмодулей.
Выполните последовательность команд в корневой директории проекта при активированном виртуальном окружении (.venv):

### Регистрация и клонирование удаленного репозитория в целевой каталог модулей
```bash
git submodule add -f https://github.com/megvii-research/NAFNet.git modules/NAFNet
```
После этого инициализируйте и обновите субмодуль, чтобы выкачать файлы кода:

```bash
cd modules/NAFNet
git submodule update --init --recursive
```

*Примечание*: Не забыть прописать в `.gitmodules` ingore = all. В противном случае, все обновления при обучении будут попадать в обновления `git`!

```ini
[submodule "modules/NAFNet"]
	path = modules/NAFNet
	url = https://github.com/megvii-research/NAFNet.git
	ignore = all
```

### Если установлен `basicsr`, удалить!


Пакет `basicsr` у `NAFNet` свой!

### Локальная сборка модифицированного фреймворка `NAFNet`

Перейдите в каталог субмодуля и запустите процедуру связывания. Флаг --no_cuda_ext является обязательным: он предотвращает компиляцию платформозависимых C++/CUDA расширений, часто вызывающих сбои сборки в WSL2, перенаправляя математические операции на стабильные нативные ядра PyTorch.

```bash
cd modules/NAFNet
python3 setup.py develop --no_cuda_ext
```

Результат выполнения: Утилита создает символическую ссылку basicsr.egg-link в site-packages, жестко замыкая любые системные вызовы пакета basicsr на физический каталог modules/NAFNet/basicsr.

*Примечание*: ключи `--no_cuda_ext` обязателен! Иначе `NAFNet` начнёт пересобирать библиотеки работы с ядром графической карты и потребует установку среды разработки `NVidia`!
