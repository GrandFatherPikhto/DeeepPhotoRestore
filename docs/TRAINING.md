# README: `run_training.py` – обучение нейросети NAFNet

## 1. Назначение

`run_training.py` – основной скрипт для **обучения модели NAFNet** на сгенерированном ранее датасете. Он выполняет:

- Загрузку данных (пары LQ/HQ) с аугментациями.
- Инициализацию модели, оптимизатора AdamW и планировщика CosineAnnealingLR.
- Цикл обучения с комбинированной функцией потерь (L1Loss + FocalFrequencyLoss).
- Периодическую валидацию на тестовой выборке (расчёт PSNR, SSIM, сохранение восстановленных изображений).
- Логирование метрик в TensorBoard, текстовый файл и CSV.
- Сохранение чекпоинтов (состояние модели, оптимизатора, планировщика).
- Возобновление обучения после прерывания (автоматически или по явному указанию).

## 2. Ключи командной строки

| Ключ | Тип | Обязательный | Описание |
|------|-----|--------------|-----------|
| `-opt PATH` | строка | **Да** | Путь к конфигурационному YAML-файлу (например, `options/train/RAW_NAFNet_NikonD600.yml`). |
| `--clean-training` | флаг | Нет | Полностью удалить папку эксперимента (`experiments/name`) перед запуском. |
| `--resume PATH` | строка | Нет | Возобновить обучение из указанного чекпоинта (переопределяет `resume_path` в конфиге). |
| `--clean` | флаг | Нет | **Устаревший** (для `run_pipeline.py`); в `run_training.py` игнорируется. |

**Пример запуска с очисткой:**  
```bash
./run_training.py -opt options/train/RAW_NAFNet_NikonD600.yml --clean-training
```

## 3. Конфигурационный YAML-файл

В этом разделе описаны секции YAML, которые **непосредственно управляют обучением**. Некоторые секции также используются `run_pipeline.py` (они отмечены).

### 3.1. Общие настройки

| Ключ | Назначение | Пример |
|------|------------|--------|
| `name` | Имя эксперимента (подставляется в пути, содержащие `{name}`, если включено). | `RAW-NAFNet-D600` |
| `manual_seed` | Фиксация генератора случайных чисел для воспроизводимости. | `42` |

### 3.2. Секция `path`

| Ключ | Назначение | Пример |
|------|------------|--------|
| `dataset_root` | Корневая папка сгенерированного датасета (подпапки `train/`, `test/`). | `"datasets/nef_nafnet"` |
| `resume_path` | Путь для сохранения / восстановления чекпоинта. Поддерживает `{name}`. | `"experiments/{name}/checkpoints/resume_nef_nafnet.pth"` |

### 3.3. Секция `datasets`

Определяет загрузчик данных для обучения.

| Ключ | Назначение | Пример |
|------|------------|--------|
| `train.type` | Класс датасета (обычно `CustomNEFPairDataset`). | `CustomNEFPairDataset` |
| `train.batch_size_per_gpu` | Размер батча (количество патчей на GPU). | `16` |
| `train.num_worker_per_gpu` | Количество процессов загрузки данных. | `4` |
| `train.auto_resume` | Автоматически продолжать обучение, если найден чекпоинт. | `true` |
| `train.gt_size` | Размер патча (высота, ширина) после кропа / ресайза. | `256` |

### 3.4. Секция `network_g` – архитектура NAFNet

Подробно параметры архитектуры описаны в отдельном разделе (см. ниже). Здесь кратко:

| Ключ | Значение | Смысл |
|------|----------|-------|
| `num_in_ch` | `4` | Входные каналы (RGGB). |
| `num_out_ch` | `3` | Выходные каналы (RGB). |
| `width` | `32` | Базовая ширина каналов. |
| `enc_blk_nums` | `[2,2,4,8]` | Блоков на этапах энкодера. |
| `middle_blk_num` | `12` | Блоков в латентном пространстве. |
| `dec_blk_nums` | `[2,2,2,2]` | Блоков на этапах декодера. |

### 3.5. Секция `train` – гиперпараметры обучения

| Ключ | Назначение | Пример |
|------|------------|--------|
| `num_epochs` | Общее количество эпох. | `150` |
| `validation_freq` | Как часто (эпох) выполнять валидацию. | `1` |
| `save_checkpoint_epoch` | Как часто (эпох) сохранять чекпоинт. | `5` |
| `optim_g.lr` | Начальная скорость обучения. | `1e-3` |
| `optim_g.weight_decay` | L2-регуляризация (обычно 0). | `0` |
| `optim_g.betas` | Параметры AdamW (`(beta1, beta2)`). | `[0.9, 0.9]` |
| `scheduler.eta_min` | Минимальное значение скорости обучения (в конце). | `1e-7` |

### 3.6. Секция `losses` – комбинированная потеря

| Ключ | Назначение | Пример |
|------|------------|--------|
| `type` | Тип лосса: `"combined"` (L1+FFL) или `"l1"`. | `"combined"` |
| `l1_weight` | Вес пространственной компоненты. | `1.0` |
| `ffl_weight` | Вес частотной компоненты. | `1.0` |
| `ffl_alpha` | Параметр фокусировки FFL (обычно 1). | `1.0` |

### 3.7. Секция `logger` – настройки логирования метрик

| Ключ | Назначение | Пример |
|------|------------|--------|
| `print_freq` | Частота вывода в консоль (каждые N шагов). | `2` |
| `use_tb_logger` | Включить TensorBoard. | `true` |
| `log_file_name` | Имя текстового файла метрик (в папке эксперимента). | `"train_progress.log"` |
| `csv_file_name` | Имя CSV-файла с метриками. | `"train_metrics.csv"` |
| `log_csv` | Записывать в CSV (рекомендуется). | `true` |
| `file_log_freq` | Частота записи в текстовый файл (каждые N шагов). | `1` |
| `log_loss_components` | Записывать отдельные компоненты L1 и FFL. | `true` |
| `include_in_console` | Какие метрики выводить в консоль. | `loss: true`, `psnr: true`, `vram: true` |
| `include_in_file_log` | Какие метрики записывать в текстовый файл. | `loss: true`, `psnr: true`, `grad_variance: true`, `log_ssim: true` и др. |

### 3.8. Секция `visuals_logger` – используется для визуального контроля (но влияет на валидацию)

| Ключ | Назначение | Пример |
|------|------------|--------|
| `output_dir` | Папка для превью (не используется обучением, но валидатор сам определяет `val_predictions`). | – |

### 3.9. Секция `pipeline_logger` – общий лог (сообщения, предупреждения, SSIM)

| Ключ | Назначение | Пример |
|------|------------|--------|
| `log_file` | Путь к файлу для сообщений (включая SSIM). | `"experiments/{name}/pipeline.log"` |

## 4. Что генерирует скрипт и куда сохраняет

| Тип данных | Путь (по умолчанию) |
|------------|----------------------|
| Чекпоинты (веса, состояние оптимизатора) | `path.resume_path` (например, `experiments/RAW-NAFNet-D600/checkpoints/resume_nef_nafnet.pth`) |
| Текстовый лог метрик (пошаговый) | `experiments/name/train_progress.log` |
| CSV-файл метрик (пошаговый) | `experiments/name/train_metrics.csv` |
| CSV-файл валидационных метрик (поэпохальный) | `experiments/name/val_metrics.csv` (создаётся автоматически) |
| TensorBoard-логи | `experiments/name/tb_logs/` |
| Восстановленные изображения (валидация) | `experiments/name/val_predictions/epoch_X_*.png` |
| Общий лог (pipeline.log) | `pipeline_logger.log_file` (например, `experiments/name/pipeline.log`) |

## 5. Пример конфигурационного файла с комментариями (для обучения)

```yaml
# ==============================================================================
# КОНФИГУРАЦИЯ ДЛЯ ОБУЧЕНИЯ NAFNET НА RAW (NIKON D600)
# ==============================================================================
name: RAW-NAFNet-D600
manual_seed: 42

path:
  dataset_root: "datasets/nef_nafnet"
  resume_path: "experiments/{name}/checkpoints/resume_nef_nafnet.pth"

datasets:
  train:
    type: CustomNEFPairDataset
    batch_size_per_gpu: 16
    num_worker_per_gpu: 4
    auto_resume: true
    gt_size: 256

network_g:
  num_in_ch: 4
  num_out_ch: 3
  width: 32
  enc_blk_nums: [2, 2, 4, 8]
  middle_blk_num: 12
  dec_blk_nums: [2, 2, 2, 2]

train:
  num_epochs: 150
  validation_freq: 1
  save_checkpoint_epoch: 5
  optim_g:
    lr: 1e-3
    weight_decay: 0
    betas: [0.9, 0.9]
  scheduler:
    eta_min: 1e-7

losses:
  type: "combined"
  l1_weight: 1.0
  ffl_weight: 1.0
  ffl_alpha: 1.0

logger:
  print_freq: 2
  use_tb_logger: true
  log_file_name: "train_progress.log"
  csv_file_name: "train_metrics.csv"
  log_csv: true
  file_log_freq: 1
  log_loss_components: true
  include_in_console:
    loss: true
    psnr: true
    vram: true
    learning_rate: false
  include_in_file_log:
    loss: true
    psnr: true
    learning_rate: true
    delta_psnr: true
    grad_variance: true
    tv_ratio: true
    vram_usage: true
    log_ssim: true

visuals_logger:
  output_dir: "experiments/{name}/debug_visuals"

pipeline_logger:
  log_file: "experiments/{name}/pipeline.log"
```

## 6. Параметры архитектуры NAFNet (подробно)

- **`num_in_ch = 4`** – входные каналы (R, G₁, G₂, B). Нейросеть работает напрямую с мозаичными данными без предварительной демозаики.
- **`num_out_ch = 3`** – выходные каналы (RGB). После последнего свёрточного слоя (обёртка) сеть выдаёт трёхканальное изображение.
- **`width = 32`** – количество фильтров в первом слое. Чем больше `width`, тем выше ёмкость модели, но больше потребление памяти.
- **`enc_blk_nums = [2, 2, 4, 8]`** – количество NAFNet-блоков на четырёх этапах энкодера. Каждый этап уменьшает разрешение в 2 раза и увеличивает число каналов в 2 раза. Например, после первого этапа разрешение `H×W`, каналов 32; после второго `H/2×W/2`, каналов 64; после третьего `H/4×W/4`, каналов 128; после четвёртого `H/8×W/8`, каналов 256.
- **`middle_blk_num = 12`** – количество блоков в латентном пространстве (наименьшее разрешение). Это самая глубокая часть сети, отвечающая за интеграцию глобального контекста.
- **`dec_blk_nums = [2, 2, 2, 2]`** – количество блоков на четырёх этапах декодера. Декодер восстанавливает разрешение и уменьшает число каналов, симметрично (не обязательно зеркально) энкодеру.

**Общее число NAFNet-блоков**: `2+2+4+8 + 12 + 2+2+2+2 = 36`. Это компактная архитектура, которая хорошо работает на небольших датасетах (как в вашем случае) и умещается в 12 ГБ VRAM при батче 16.

## 7. Вывод

`run_training.py` – это полноценный цикл обучения нейросети для задачи восстановления изображений с малогабаритных CFA-сенсоров. Он обеспечивает:

- Воспроизводимость за счёт фиксации seed и чекпоинтов.
- Гибкую настройку через YAML (архитектура, гиперпараметры, логирование).
- Автоматическое возобновление после прерывания.
- Сохранение всех метрик для последующего анализа (CSV, TensorBoard).
- Визуальный контроль качества (валидационные картинки, SSIM).

Скрипт готов к запуску на GPU с минимальным вмешательством пользователя. Результаты обучения (веса, логи, графики) могут быть непосредственно использованы в диссертации.
