В репозитории RAW-to-sRGB под датасетом (набором данных) понимается коллекция парных фотографий, где одно и то же изображение представлено в двух разных форматах: «сыром» RAW (с матрицы камеры) и стандартном цветном sRGB (готовая картинка).
Эти данные необходимы для обучения нейросети, которая учится автоматически превращать необработанные кадры в красивые и качественные фотографии.
## Какие датасеты используются в этом проекте?
В разделе Dataset этого репозитория авторы предлагают использовать два конкретных набора данных:

* Zurich RAW to RGB dataset: Набор, содержащий фотографии, сделанные на смартфон с RAW-сенсором, и соответствующие им эталонные sRGB-снимки, сделанные на зеркальную камеру Canon.
* SR-RAW Dataset: Набор данных, который авторы репозитория дополнительно обработали. Он используется для одновременного улучшения разрешения (Super-Resolution) и цветокоррекции RAW-изображений.

## Из чего состоит такой датасет?
Каждая папка в таком наборе обычно содержит:

   1. Входные данные (Inputs): Файлы с расширениями вроде .ARW, .CR2, .DNG или массивы NumPy. Это сырые, блеклые и мозаичные данные с матрицы фотоаппарата.
   2. Целевые данные (Targets / Ground Truth): Готовые изображения в формате .PNG или .JPG. Это идеальный результат цветопередачи, к которому должна стремиться нейросеть в процессе обучения.

ШАГ 2. Алгоритмы сжатия (Создание обучающих пар)
Чтобы обучить модель «убирать» сжатие, вам нужно программно испортить исходные качественные изображения. Для этого в Python используют библиотеку Pillow (PIL).
Алгоритм 1 (JPEG-блоки): Сжатие в стандартный JPEG с низким качеством (quality=10 или 20). Это создает характерные «квадраты» (блочные артефакты) и размывает мелкие детали.
Алгоритм 2 (Даунсэмплинг + JPEG): Сначала уменьшить разрешение картинки в 2 или 4 раза (Bicubic downsampling), а затем применить JPEG-сжатие. Это классический подход для обучения современных моделей-апскейлеров (Super-Resolution), таких как Real-ESRGAN.
ШАГ 3. Существующие PyTorch модели
Для восстановления изображений после сжатия лучше всего брать готовые архитектуры из области Image Restoration. Их легко развернуть на PyTorch:
NAFNet (Nonlinear Activation Free Network) — одна из лучших и самых быстрых современных архитектур для удаления шумов и артефактов сжатия. Работает без тяжелых функций активации.
SwinIR — мощная модель на базе трансформеров, в которой есть официальный готовый режим для JPEG Artifact Reduction.
Restormer — еще один топовый трансформер для восстановления структуры и мелких деталей на изображениях.
ШАГ 4. Реализация пайплайна на Python
Ниже представлен готовый скрипт, который автоматически выполняет Шаг 4.c (разбиение на Train/Test в пропорции 95/5) и подготавливает пары «сжатое изображение 
 оригинал».

import os
import shutil
import random
from PIL import Image

# 1. Настройка путей
SOURCE_RAW_DIR = "path/to/your/downloaded/raw_images" # Папка с исходным датасетом
BASE_OUT_DIR = "dataset_prepared"
TRAIN_DIR = os.path.join(BASE_OUT_DIR, "train")
TEST_DIR = os.path.join(BASE_OUT_DIR, "test")

# Создаем структуру папок
for folder in [TRAIN_DIR, TEST_DIR]:
    os.makedirs(os.path.join(folder, "hq_targets"), exist_ok=True) # Оригиналы (Ground Truth)
    os.makedirs(os.path.join(folder, "lq_inputs"), exist_ok=True)  # Сжатые (Inputs)

# 2. Функция для имитации сжатия (Шаг 2)
def compress_image(img_path, output_path, quality=15):
    # Примечание: Для чтения .DNG/.RAW файлов в Python используйте библиотеку rawpy
    # Ниже приведен пример для обычного RGB/PNG (предполагая, что RAW уже конвертирован в sRGB)
    with Image.open(img_path) as img:
        # Сохраняем во временный JPEG с низким качеством
        img.save(output_path, "JPEG", quality=quality)

# 3. Разбиение датасета (Шаг 4.c)
all_images = [f for f in os.listdir(SOURCE_RAW_DIR) if f.lower().endswith(('.dng', '.png', '.jpg'))]
random.seed(42) # Фиксируем сид для воспроизводимости
random.shuffle(all_images)

split_idx = int(len(all_images) * 0.95)
train_files = all_images[:split_idx]
test_files = all_images[split_idx:]

def process_split(files, destination_folder):
    for file_name in files:
        src_path = os.path.join(SOURCE_RAW_DIR, file_name)
        
        # Копируем оригинал в папку HQ
        hq_path = os.path.join(destination_folder, "hq_targets", file_name)
        shutil.copy(src_path, hq_path)
        
        # Создаем сжатую копию в папку LQ
        lq_name = os.path.splitext(file_name)[0] + ".jpg"
        lq_path = os.path.join(destination_folder, "lq_inputs", lq_name)
        compress_image(src_path, lq_path, quality=20)

print("Обработка тренировочной выборки...")
process_split(train_files, TRAIN_DIR)

print("Обработка тестовой выборки...")
process_split(test_files, TEST_DIR)
print("Готово!")

## Что такое PyTorch?

PyTorch — это одна из самых популярных библиотек с открытым исходным кодом для машинного обучения и создания нейросетей, разработанная лабораторией искусственного интеллекта компании Meta (Facebook).
На ней написаны многие современные ИИ, включая большие языковые модели и генераторы изображений.
Главные особенности PyTorch
Динамический граф вычислений (Dynamic Computation Graph): Нейросеть строится «на лету» прямо во время выполнения кода. Это позволяет легко менять архитектуру модели в процессе работы, использовать стандартные циклы Python (if, for) и значительно упрощает отладку кода.
Тензоры вместо массивов: Главный объект в PyTorch — это Tensor (тензор). Он похож на многомерный массив из библиотеки NumPy, но оптимизирован для работы на видеокартах (GPU), что ускоряет математические расчеты в десятки раз.
Автоматическое дифференцирование (autograd): PyTorch сам считает градиенты (производные), которые необходимы для корректировки весов нейросети при ее обучении. Вам не нужно вручную писать сложные математические формулы для обратного распространения ошибки.
Почему его выбирают для проектов вроде вашего?
Простой и понятный код: Написание нейросети на PyTorch очень похоже на написание обычного скрипта на Python (так называемый Pythonic style).
Огромная экосистема: Почти все современные научные статьи по компьютерному зрению (удаление артефактов, апскейлинг, обработка RAW) выкладывают свой код именно на PyTorch.
Гибкость: Вы можете взять готовую архитектуру (например, SwinIR или NAFNet) и легко изменить в ней пару слоев под свои задачи сжатия.
Как выглядит простая нейросеть на PyTorch?
Вот пример того, как в PyTorch создается простейший слой, который принимает изображение и пытается его обработать:
python
import torch
import torch.nn as nn

# Создаем класс своей нейросети
class SimpleRestorationModel(nn.Module):
    def __init__(self):
        super().__init__()
        # Слой, который обрабатывает картинку (свертка)
        self.conv = nn.Conv2d(in_channels=3, out_channels=3, kernel_size=3, padding=1)

    def forward(self, x):
        # Описываем, как данные проходят через сеть
        return self.conv(x)

# Создаем модель
model = SimpleRestorationModel()

# Генерируем случайную "картинку" (размер 1х3х256х256) и отправляем в модель
dummy_input = torch.randn(1, 3, 256, 256)
output = model(dummy_input)

## Мы учим модель с нуля?

В зависимости от вашей задачи, в PyTorch можно делать и то, и другое. Однако для вашей конкретной задачи (устранение артефактов сжатия) всегда используют комбинированный подход, который экономит недели вычислений.
Вот как это работает:
## 1. Подключение готовой модели (Предобученная модель / Pre-trained)
Вы скачиваете веса модели, которую авторы уже обучили на миллионах картинок (например, на датасете DIV2K).

* Плюсы: Модель уже «умеет» видеть границы, текстуры и понимать структуру изображений.
* Минусы: Она может быть обучена на «стандартном» JPEG-сжатии, а у вас в ТЗ специфическое сжатие или работа с RAW-данными.

## 2. Обучение с нуля (From Scratch)
Вы берете «пустую» архитектуру (нейросеть, которая заполнена случайными числами) и заставляете её учиться только на вашем датасете.

* Плюсы: Идеально подстроится под ваши специфические данные.
* Минусы: Требует огромного датасета, мощной видеокарты (GPU) и очень много времени.

------------------------------
## Как правильно поступить вам? (Дообучение / Fine-Tuning)
Идеальный сценарий, который заложен в вашем ТЗ (пункт 3: «их легко... развернуть и дообучить»), выглядит так:

   1. Скачиваете готовую модель (например, SwinIR или NAFNet), предобученную на общую задачу восстановления изображений.
   2. Замораживаете или оставляете открытыми её базовые слои.
   3. Запускаете дообучение (Fine-Tuning) на вашем новом датасете из 5 000 фотографий, который вы собрали на Шаге 4.

Нейросеть не будет заново учиться понимать, где на фото трава, а где лицо. Она лишь «донастроится» на особенности вашего алгоритма сжатия и RAW-формата. Это займет в разы меньше времени и даст максимальное качество.

## NAFNet

Для работы с изображениями и выполнения вашей задачи (устранение артефактов сжатия) вам нужен ИИ из сферы Computer Vision (компьютерного зрения). В отличие от текстовых моделей, эти нейросети состоят из сверточных слоев (CNN) или визуальных трансформеров (Vision Transformers), которые созданы специально для обработки пикселей.
Вам стоит выбрать одну из трех готовых нейросетей, которые сейчас являются золотым стандартом в этой области:
## 1. NAFNet (Nonlinear Activation Free Network) — Рекомендуется
Самый практичный выбор для запуска на домашнем компьютере.

* Почему она: Это очень «легкая» и быстрая нейросеть. Авторы убрали из неё тяжелые функции активации, благодаря чему она тратит гораздо меньше видеопамяти при обучении, но выдает топовое качество.
* Для чего: Идеально стирает JPEG-блоки («кубики») и восстанавливает гладкость текстур.

## 2. SwinIR (Image Restoration Using Swin Transformer)
Самая мощная и умная модель, построена на базе трансформеров (технология, похожая на ту, что используется в ChatGPT, но адаптированная под картинки).

* Почему она: Невероятно круто восстанавливает мелкие детали (волосы, шерсть, текст, текстуру ткани), которые были «съедены» сжатием.
* Минусы: Требует много видеопамяти (желательно карту от Nvidia с 8-12 ГБ VRAM для комфортного дообучения).

## 3. Real-ESRGAN
Если вам нужно не просто убрать сжатие, а еще и увеличить разрешение (сделать апскейл, например, в 2 или 4 раза), то эта модель — лучший выбор. Она предобучена на то, чтобы восстанавливать сильно испорченные цифровые снимки.

## Где запускать на Windows или на Linux

Проекты в сфере Deep Learning (и NAFNet в частности) однозначно лучше гонять на Linux (лялихе).
Вот 3 главные причины, почему Linux в данном случае намного эффективнее Windows:

   1. Скорость работы (PyTorch 2.0+): В современных версиях PyTorch есть мощный режим ускорения кода torch.compile(). На Linux он работает «из коробки» и дает прирост скорости обучения до 15–30%. На Windows эта функция до сих пор официально не поддерживается.
   2. Меньше проблем с компиляцией (setup.py): В инструкции NAFNet есть шаг python setup.py develop. Он компилирует C++/CUDA расширения под капотом. На Windows для этого придется ставить тяжелый Microsoft Visual Studio и часто ловить ошибки несовместимости компиляторов. На Linux все ставится одной командой.
   3. Эффективное управление памятью: Linux гораздо лучше и стабильнее работает с оперативной памятью (RAM) и видеопамятью (VRAM) при параллельной загрузке больших датасетов через DataLoader.

## Компромиссный вариант: WSL 2 (Windows Subsystem for Linux)
Если вы не хотите полностью сносить Windows и ставить Linux второй системой, идеальный выход — WSL 2 (интегрированная Linux-среда прямо внутри Windows).

* Вы работаете в привычной Windows.
* При этом в терминале у вас полноценный Ubuntu Linux.
* Самое главное: Nvidia сейчас официально поддерживает проброс видеокарты в WSL 2. Ваша RTX 4070 Ti будет работать там со стопроцентной производительностью и поддержкой CUDA.

## WSL

Да, вы получите полный и прямой доступ к вашей RTX 4070 Ti из WSL 2. Начиная с Windows 10 (сборка 21H2) и в Windows 11, технология Nvidia CUDA в WSL работает официально и «из коробки».
Производительность видеокарты внутри WSL 2 составляет около 95–98% от работы на чистом Linux. Потери на виртуализацию практически незаметны.
## Что нужно сделать, чтобы WSL увидел вашу 4070 Ti?
Секрет в том, что вам НЕ нужно устанавливать графический драйвер Nvidia внутри самого Linux (в WSL). Пайплайн выглядит следующим образом:

   1. Драйвер на Windows: Вы просто устанавливаете самый свежий стандартный драйвер Game Ready или Studio на вашу основную Windows. Он сам «пробросит» видеокарту внутрь Linux.
   2. CUDA Toolkit в WSL: А вот саму библиотеку разработки CUDA нужно будет поставить внутри терминала Ubuntu (WSL). Важно выбрать версию именно для WSL-Ubuntu (на сайте Nvidia есть специальная вкладка Linux -> x86_64 -> WSL-Ubuntu).

## Как проверить, что всё связалось?
После того как вы запустите WSL и установите там PyTorch, вы сможете запустить этот короткий тест в терминале Ubuntu:

python3 -c "import torch; print('CUDA доступна:', torch.cuda.is_available()); print('Ваша карта:', torch.cuda.get_device_name(0))"

## Скрипт автоматической подготовки датасета

import osimport shutilimport randomfrom PIL import Image
# 1. Настройка путейSOURCE_DIR = "source_images"  # Сюда ты складываешь исходные чистые фотоBASE_OUT_DIR = "dataset_ready"
TRAIN_HQ = os.path.join(BASE_OUT_DIR, "train/hq_targets") # Оригиналы для обученияTRAIN_LQ = os.path.join(BASE_OUT_DIR, "train/lq_inputs")  # Сжатые для обученияTEST_HQ = os.path.join(BASE_OUT_DIR, "test/hq_targets")   # Оригиналы для тестаTEST_LQ = os.path.join(BASE_OUT_DIR, "test/lq_inputs")    # Сжатые для теста
# Автоматически создаем всю структуру папокfor folder in [TRAIN_HQ, TRAIN_LQ, TEST_HQ, TEST_LQ]:
    os.makedirs(folder, exist_ok=True)
# 2. Функция сжатия (Шаг 2 из ТЗ)def compress_image(src_path, dest_path, quality_level=15):
    """Открывает картинку и пересохраняет с жестким JPEG-сжатием"""
    with Image.open(src_path) as img:
        # Конвертируем в RGB на случай, если попался PNG с прозрачностью (RGBA)
        if img.mode != 'RGB':
            img = img.convert('RGB')
        # Сохраняем с низким качеством, порождая артефакты
        img.save(dest_path, "JPEG", quality=quality_level)
# 3. Чтение и перемешивание файловvalid_extensions = ('.jpg', '.jpeg', '.png', '.bmp', '.tif', '.tiff')all_images = [f for f in os.listdir(SOURCE_DIR) if f.lower().endswith(valid_extensions)]
if not all_images:
    print(f"❌ Ошибка: Папка '{SOURCE_DIR}' пуста! Добавь туда исходные картинки.")
    exit()

random.seed(42)  # Фиксируем сид, чтобы разделение всегда было одинаковым
random.shuffle(all_images)
# Высчитываем пропорцию 95% / 5% (Шаг 4.c из ТЗ)split_idx = int(len(all_images) * 0.95)# Если картинок слишком мало для теста, отдаем хотя бы одну в тестif split_idx == len(all_images) and len(all_images) > 1:
    split_idx -= 1
train_files = all_images[:split_idx]test_files = all_images[split_idx:]
# 4. Функция распределения по папкамdef process_images(file_list, hq_dir, lq_dir, split_name):
    print(f"Обработка выборки [{split_name}] — {len(file_list)} шт...")
    for file_name in file_list:
        src_file_path = os.path.join(SOURCE_DIR, file_name)
        
        # Переносим оригинал (HQ Target) в неизменном виде (но в формате .png для стабильности нейросети)
        base_name = os.path.splitext(file_name)[0]
        hq_file_path = os.path.join(hq_dir, f"{base_name}.png")
        
        with Image.open(src_file_path) as img:
            img.save(hq_file_path, "PNG")
        
        # Создаем сжатый дубликат (LQ Input) в формате .jpg
        lq_file_path = os.path.join(lq_dir, f"{base_name}.jpg")
        compress_image(src_file_path, lq_file_path, quality_level=15)
# Запуск обработки
process_images(train_files, TRAIN_HQ, TRAIN_LQ, "TRAIN (95%)")
process_images(test_files, TEST_HQ, TEST_LQ, "TEST (5%)")

print("\n🎉 Всё готово! Проверь папку 'dataset_ready'. Она полностью укомплектована.")

## Флаг --no_cuda_ext

Флаг --no_cuda_ext (сокращение от no CUDA extensions) дословно означает «не компилировать кастомные расширения CUDA при установке». 

GitHub
Пусть это название тебя не пугает — твоя видеокарта RTX 4070 Ti всё равно будет работать на полную мощность.
Вот почему авторы NAFNet добавили этот флаг в инструкцию: 

GitHub
1. Твоя 4070 Ti всё равно в деле
Вся основная магия (свёртки, обучение, подсчёт градиентов) выполняется силами самого PyTorch, который мы уже установили с поддержкой CUDA. PyTorch сам по себе прекрасно умеет загружать твою видеокарту без каких-либо сторонних дополнений.
2. Защита от «ада зависимостей» (Dependency Hell)
Если запустить сборку без этого флага (python setup.py develop), скрипт попытается взять исходный C++ и CUDA код из папок репозитория и скомпилировать его прямо у тебя на компьютере под твою систему.
Для этого системе требуются идеально совпадающие друг с другом версии компилятора gcc, библиотек g++ и CUDA Toolkit (nvcc). Стоит одной цифре в версиях не совпасть — сборка намертво упадёт с кучей непонятных ошибок компиляции.
Флаг --no_cuda_ext отключает эту сложную компиляцию «из исходников». Проект ставится легко, быстро и стабильно, а кастомные операции заменяются стандартными и быстрыми аналогами из уже готового PyTorch.

## Скрипт для загрузки картинок

Супер, то что нужно! Структуру твоего CSV-файла я вижу — здесь всё идеально разложено по полочкам, разделитель — запятая.
Но есть один критический нюанс: ссылки ведут на .NEF (сырой RAW от камер Nikon) или на тяжеленный несжатый .TIF [0.1].
Проблема в том, что Python-библиотека Pillow (через которую мы собирались портить картинки) не умеет из коробки открывать файлы .NEF. Ей на вход нужно подавать уже сконвертированную стандартную RGB-картинку.
Поэтому давай сделаем умный скрипт. Он будет скачивать файлы по ссылкам из твоего CSV, а если файл окажется в формате .NEF, скрипт автоматически использует библиотеку rawpy, чтобы превратить его в нормальное изображение, и сразу сохранит в папку source_images.
Вот готовый код. Создай файл download_and_convert.py в папке Tanahen:

import osimport pandas as pdimport requestsimport rawpyfrom PIL import Imageimport io
# 1. НастройкиCSV_FILE = "RAISE_metadata.csv"  # Имя твоего CSV-файлаOUTPUT_DIR = "source_images"     # Папка, куда полетят готовые чистые картинкиMAX_IMAGES = 10                  # Для первого теста скачаем 10 штук

os.makedirs(OUTPUT_DIR, exist_ok=True)
# 2. Читаем CSV
print("Читаем CSV файл метаданных...")df = pd.read_csv(CSV_FILE)
# 3. Качаем и конвертируемdownloaded = 0
for index, row in df.iterrows():
    if downloaded >= MAX_IMAGES:
        break
        
    # Пытаемся взять ссылку на TIFF (проще читать) или на NEF (RAW)
    url_tiff = row.get('TIFF')
    url_nef = row.get('NEF')
    
    # Предпочтение отдаем TIFF, если есть, так как его не надо декодировать из RAW
    url = url_tiff if (pd.notna(url_tiff)) else url_nef
    
    if not url or pd.isna(url):
        continue
        
    base_name = row.get('File')
    dest_jpg_path = os.path.join(OUTPUT_DIR, f"{base_name}.jpg")
    
    # Если уже скачивали — пропускаем
    if os.path.exists(dest_jpg_path):
        print(f"Файл {base_name} уже существует, пропускаю...")
        downloaded += 1
        continue

    print(f"[{downloaded+1}/{MAX_IMAGES}] Качаю: {base_name}...")
    
    try:
        response = requests.get(url, timeout=45)
        if response.status_code != 200:
            print(f"❌ Ошибка загрузки {base_name} (Код: {response.status_code})")
            continue
            
        # Если скачали RAW (.NEF), его нужно проявить в RGB
        if url.lower().endswith('.nef'):
            print(f"⚙️ Проявляю RAW (.NEF) для {base_name}...")
            with rawpy.imread(io.BytesIO(response.content)) as raw:
                # postprocess() превращает матрицу RAW в привычный RGB массив
                rgb_array = raw.postprocess(use_camera_wb=True) 
                img = Image.fromarray(rgb_array)
        else:
            # Если это TIFF, просто открываем его через Pillow
            img = Image.open(io.BytesIO(response.content))
            
        # Сохраняем в папку как качественный эталонный JPEG (100% качество)
        img.save(dest_jpg_path, "JPEG", quality=100)
        print(f"✅ Успешно сохранен: {dest_jpg_path}")
        downloaded += 1
        
    except Exception as e:
        print(f"❌ Сбой при обработке {base_name}: {e}")

print(f"\n🎉 Скрипт отработал! В папке '{OUTPUT_DIR}' теперь лежат готовые чистые файлы.")

# 🛠️ Проект Tanahen: Автоматическое удаление артефактов JPEG-сжатия с помощью нейросети NAFNet
Этот проект посвящен автоматическому восстановлению качества изображений (Image Restoration). Главная цель — обучить нейросеть находить, сглаживать и убирать «кубики» (блочные артефакты), размытие и шумы, которые появляются на фотографиях после сильного сжатия алгоритмом JPEG.

Проект развернут локально в среде **Linux (Ubuntu под WSL 2)** на базе фреймворка **PyTorch** с аппаратным ускорением на видеокарте **NVIDIA RTX 4070 Ti (12GB VRAM)**.
---## 🧭 ЧТО МЫ СДЕЛАЛИ (Пошаговый разбор пайплайна)
Мы настроили полный цикл машинного обучения (Data Science Pipeline), состоящий из 4 ключевых этапов:
### 1. Добыча «чистых» эталонов (Ground Truth)Нейросеть не может научиться делать картинку качественной, если не видит идеального примера. 
* С помощью скрипта `download_and_convert.py` мы подключились к профессиональному RAW-датасету **RAISE** [0.1]. 
* Скрипт прочитал CSV-таблицу метаданных [0.1], вытащил прямые ссылки [0.1], скачал тяжелые файлы цифровых негативов камер Nikon (`.NEF`) [0.1] и с помощью библиотеки `rawpy` «проявил» их в чистейшие RGB-картинки без потерь, сохранив их в папку `source_images`.
### 2. Искусственное ухудшение данных (Генерация пар)Чтобы нейросеть поняла, *что именно* ей нужно исправлять, мы создали для нее пары картинок «Было \(\rightarrow\) Стало».
* Скрипт `prepare_dataset.py` взял наши чистые эталоны из `source_images` и жестко испортил их алгоритмом сжатия Pillow JPEG с качеством `quality=15`.* Картинки покрылись характерными квадратными артефактами (JPEG Artifacts).
### 3. Разделение данных (Train / Test Split)Чтобы честно проверить, действительно ли нейросеть *научилась* восстанавливать фото, или она просто *зазубрила* тестовые кадры, тот же скрипт `prepare_dataset.py` разделил файлы в пропорции:* **Train (Обучающая выборка)** — папки, по которым нейросеть «зубрит» материал и подстраивает свои веса.* **Test/Val (Проверочная выборка)** — папки с картинками, которые нейросеть во время учебы никогда не видит. На них движок раз в несколько тысяч шагов проверяет реальное качество работы модели.

Все данные автоматически разложились в созданную папку `dataset_ready`:```text
dataset_ready/
├── train/
│   ├── hq_targets/  # Чистые оригиналы для учебы
│   └── lq_inputs/   # Испорченные сжатием картинки для учебы
└── test/
    ├── hq_targets/  # Чистые оригиналы для проверки
    └── lq_inputs/   # Испорченные картинки для проверки
```
### 4. Сборка и запуск ИИ-движкаВ качестве архитектуры ИИ мы выбрали **NAFNet** (Nonlinear Activation Free Network) — современную, очень быструю нейросеть для реставрации изображений [0.1].
* Мы создали файл конфигурации `train_NAFNet_JPEG.yml`. В нем мы прописали жесткие абсолютные пути к нашей папке `dataset_ready`, указали размер «патчей» (`gt_size: 256` — нейросеть режет большие фото на кусочки 256x256 для удобства), размер батча (`batch_size: 8` — сколько кусочков за раз переваривает видеокарта) и параметры оптимизатора AdamW.
* Мы запустили главный движок обучения: `python basicsr/train.py -opt options/train/Tanahen/train_NAFNet_JPEG.yml` [0.1].

## NAFNet

Представь, что у тебя есть друг-художник, которому дали задачу: «Вот тебе зашакаленная, размытая фотка из интернета, сделай из неё чёткий шедевр».
Обычный человек взял бы инструмент «Резкость» в Фотошопе, но от этого полезут новые шумы. А умный художник делает так: он внимательно всматривается в картинку, понимает, где там были волосы, где кирпичная стена, а где просто гладкое небо, и аккуратно дорисовывает правильные пиксели, стирая квадраты сжатия.
NAFNet — это как раз и есть такой цифровой художник, только виртуальный [0.1].
Давай разберем по косточкам, как он устроен, откинув сложную научную терминологию.
------------------------------
## 🧠 1. Почему это «Нейросеть» (Нейронка)?
Внутри Python мы написали строчку type: NAFNet. Под капотом PyTorch создал структуру, похожую на слоёный пирог из математических формул (слоёв).
Когда в этот пирог залетает «шакальная» картинка, она проходит через десятки слоев:

* Первые слои замечают простые вещи: «О, тут горизонтальная линия, а тут вертикальный контур».
* Средние слои начинают складывать линии в узоры: «Так, эти линии похожи на текстуру кирпича, а вот эти — на кусок человеческого лица».
* Финальные слои сопоставляют это с накопленным опытом и выдают готовую чистую картинку.

------------------------------
## 🕵️‍♂️ 2. Что значат эти буквы: N-A-F-Net?
Полное название расшифровывается как Nonlinear Activation Free Network. Звучит страшно, но для программиста на Python вся суть кроется в одном слове — Оптимизация.
В любой стандартной нейросети (например, в той, на которой работает ChatGPT или генераторы картинок) между слоями обязательно стоят специальные математические функции-переключатели. В коде ты их мог видеть как nn.ReLU() или nn.GELU().
Они нужны, чтобы нейросеть могла решать сложные нелинейные задачи. Но у них есть огромный минус: они жрут прорву оперативной и видеопамяти, замедляя работу видеокарты.
Авторы NAFNet совершили гениальный прорыв [0.1]: они полностью выкинули эти тяжелые функции из кода!
Вместо них они применили простую школьную математику — умножение. Они берут данные из слоя, делят их пополам и просто умножают одну половину на другую. Оказалось, что для видеокарты это колоссально легче физически, а качество восстановления картинок получается даже выше, чем со сложными формулами [0.1]!
------------------------------
## 🎨 3. Как это выглядит в коде (на пальцах)
Помнишь, в конфиге ты менял строчки enc_blk_nums, middle_blk_num и dec_blk_nums? Это архитектура типа U-Net (или «песочные часы»).
NAFNet работает по принципу сжатия и растяжения:

   1. Вход (enc_blk_nums): Нейросеть берет твою картинку 256x256 пикселей и начинает уменьшать её в размерах (сжимать), но при этом увеличивает количество каналов (глубину анализа). Она как бы превращает пиксели в «смысловой вектор».
   2. Горлышко (middle_blk_num): На самом глубоком уровне (где картинка сжата сильнее всего) модель применяет те самые 12 мощных блоков, которые мы прописали. Здесь происходит главный анализ геометрии кадра.
   3. Выход (dec_blk_nums): Модель начинает разворачивать картинку обратно до исходного размера 256x256, убирая по пути весь мусор и JPEG-кубики.

* Она SOTA (State-of-the-Art): на момент своего выхода она побила мировые рекорды по качеству удаления размытия и артефактов, обогнав даже тяжеленные трансформеры [0.1].

import osimport torchimport numpy as npfrom PIL import Imagefrom basicsr.models.archs.nafnet_arch import NAFNet
# ==================== НАСТРОЙКИ ====================# 1. Путь к файлу весов модели (выбери самый свежий или latest)MODEL_PATH = "NAFNet/experiments/NAFNet-JPEG-4070Ti/models/net_g_latest.pth"
# 2. Картинка, которую ты хочешь исправить (положи её в папку Tanahen)INPUT_IMAGE = "my_shakal_photo.jpg" 
# 3. Куда сохранить результат работы нейросетиOUTPUT_IMAGE = "fixed_by_nafnet.png"# ===================================================
def main():
    if not os.path.exists(INPUT_IMAGE):
        print(f"❌ Ошибка: Положи зашакаленную картинку '{INPUT_IMAGE}' в папку проекта!")
        return

    # Настраиваем видеокарту 4070Ti
    device = torch.device('cuda' if torch.cuda.is_available() else 'cpu')
    print(f"🚀 Запускаем нейросеть на: {device}")

    # 1. Собираем пустую архитектуру NAFNet (точно такую же, как в конфиге)
    model = NAFNet(
        img_channel=3, 
        width=32, 
        middle_blk_num=12, 
        enc_blk_nums=[2, 2, 4, 8], 
        dec_blk_nums=[2, 2, 2, 2]
    )
    
    # 2. Загружаем в неё обученные веса из файла .pth
    print("🧠 Загружаем мозги нейросети...")
    checkpoint = torch.load(MODEL_PATH, map_location=device)
    # В BasicSR веса лежат внутри словаря под ключом 'params'
    if 'params' in checkpoint:
        model.load_state_dict(checkpoint['params'])
    else:
        model.load_state_dict(checkpoint)
        
    model.to(device)
    model.eval() # Переводим модель в режим предсказания

    # 3. Подготавливаем картинку для нейросети
    print("📸 Читаем и подготавливаем изображение...")
    img_pil = Image.open(INPUT_IMAGE).convert('RGB')
    
    # Превращаем картинку в массив чисел от 0.0 до 1.0
    img_np = np.array(img_pil).astype(np.float32) / 255.0
    
    # Меняем порядок осей с (Высота, Ширина, Цвета) на (Цвета, Высота, Ширина) — так любит PyTorch
    img_tensor = torch.from_numpy(np.transpose(img_np, (2, 0, 1))).float()
    
    # Добавляем фейковую ось "батча" в начало, чтобы получился тензор размера (1, 3, H, W)
    img_tensor = img_tensor.unsqueeze(0).to(device)

    # 4. Сама магия ИИ
    print("🪄 Нейросеть убирает артефакты сжатия...")
    with torch.no_grad(): # Отключаем подсчет градиентов, чтобы видеокарта не тратила память
        output_tensor = model(img_tensor)

    # 5. Превращаем тензор обратно в обычную картинку
    output_tensor = output_tensor.squeeze(0).clamp(0, 1).cpu() # Убираем ось батча и обрезаем значения от 0 до 1
    output_np = np.transpose(output_tensor.numpy(), (1, 2, 0)) # Возвращаем оси (H, W, C)
    output_np = (output_np * 255.0).astype(np.uint8) # Переводим обратно в формат пикселей 0-255

    # Сохраняем результат
    fixed_img = Image.fromarray(output_np)
    fixed_img.save(OUTPUT_IMAGE)
    print(f"🎉 Готово! Результат сохранен в файл: {OUTPUT_IMAGE}")
if __name__ == '__main__':
    main()

## В чём разница между NAFNet и RAW-to-sRGB?
Представь, что у тебя есть две разные проблемы с машинами, и ты пытаешься применить к ним один и тот же ключ:

   1. NAFNet (то, что мы делаем сейчас) — это «Автослесарь/Реставратор»:
   * Его задача: Взять стандартную, готовую картинку sRGB (JPEG), которую кто-то помял и испортил сжатием, и починить её — убрать кубики, вернуть резкость. Он работает в пространстве обычных цветных пикселей.
   2. RAW-to-sRGB (проект по ссылке) — это «Переводчик/Цифровая лаборатория»:
   * Его задача: Он вообще не умеет чинить испорченные JPEG-и. Он занимается тем, что берёт сырые, блеклые, зеленоватые данные напрямую с матрицы камеры (RAW) и учится превращать их в красивую, сочную цветную фотографию (sRGB), имитируя работу процессора дорогого фотоаппарата.
   
## Почему их нельзя объединять в один пайплайн?
Если ты попытаешься засунуть этот репозиторий в наш текущий проект, получится каша:

* Наш скрипт-генератор prepare_dataset.py специально создаёт JPEG-артефакты.
* Проект RAW-to-sRGB сойдёт с ума, если подсунуть ему JPEG. Он ожидает на вход чистые, несжатые RAW-файлы (массивы данных без цвета). Он просто не поймет, что делать с «квадратами» сжатия, потому что в RAW-формате таких артефактов в принципе не бывает.

## 💡 Как эти два проекта могли бы жить вместе? (В идеальном мире)
Они могли бы работать только как конвейер из двух абсолютно разных этапов:

   1. Сначала ты берёшь фотку с камеры телефона в формате RAW.
   2. Пропускаешь её через нейросеть RAW-to-sRGB, чтобы получить идеальный цветной кадр.
   3. Потом ты сохраняешь его в JPEG, пересылаешь в телеграме, он сжимается и «шакалится».
   4. И вот тут ты зовёшь наш NAFNet, чтобы он убрал эти артефакты сжатия!

Так что для твоей текущей задачи из ТЗ (устранение артефактов сжатия) — оставайся на NAFNet. Он создан именно под это, и твоя 4070 Ti сейчас делает ровно то, что нужно.

## Проверка загрузки видеокарты

Без паники! Твоя интуиция тебя не обманывает, но здесь есть два логичных объяснения, почему твоя RTX 4070 Ti ведёт себя подозрительно тихо.
## Причина 1. Самая вероятная: У тебя микро-датасет
В логах написано: Number of train images: 9. Это крошечный объём.
Видеокарта выполняет один шаг обучения (вычисления над батчем из 8 картинок) за доли секунды. После этого она встает и «ждет», пока процессор (CPU) подготовит следующую порцию данных. [1] 
Поскольку картинок мало, 4070 Ti успевает остыть между шагами. Вентиляторы на современных картах (технология 0dB Fan / Freeze) вообще не крутятся, пока графический чип не нагреется выше 55–60°C. Карта просто считает твой микро-тест в пассивном режиме охлаждения. [2, 3, 4] 
------------------------------
## Причина 2. Ошибка «холостого» CPU-обучения
Иногда PyTorch из-за внутренних настроек WSL может молча сбросить вычисления на процессор.
Давай устроим тотальную проверку прямо во время работы скрипта.
## Шаг 1. Жестко привяжем CUDA при запуске
Останови обучение (Ctrl + C) и запусти его заново, добавив в самое начало флаг, который принудительно заставит Python использовать только первую видеокарту NVIDIA: [5] 

CUDA_VISIBLE_DEVICES=0 python3 basicsr/train.py -opt options/train/Tanahen/train_NAFNet_JPEG.yml

## Шаг 2. Заглянем видеокарте в «паспорт»
Пока команда работает и в консоли висит пауза или идут шаги, открой второе (соседнее) окно терминала Ubuntu и введи команду:

nvidia-smi

Она выведет подробную таблицу состояния видеокарты. Обрати внимание на эти параметры: [6] 

   1. GPU-Util (Загрузка): Если там 0% — счёт действительно идёт на процессоре. Если прыгает от 15% до 80% — всё в порядке, карта считает.
   2. Memory-Usage (Память): Там должно быть занято примерно 3–6 GB из твоих 12 GB.
   3. Processes (Процессы): В самом низу таблицы в списке процессов должна быть строчка, где написано python3.

Если процесс python3 есть в таблице и память занята — твоя 4070 Ti пашет на полную, просто ей «холодно» от такого маленького объёма картинок.
