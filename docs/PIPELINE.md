# README: `run_pipeline.py` – предобученческий конвейер

## 1. Назначение

`run_pipeline.py` – это главный скрипт **предобученческой проверки** и генерации датасета. Он выполняет следующие задачи:

- Генерирует (или перегенерирует) обучающие пары LQ/HQ в соответствии с физической моделью деградации (сжатие, PSF, маска Байера, коррелированный шум).
- Загружает сгенерированные данные и выполняет **визуальный контроль** (сохраняет примеры LQ и HQ в папку визуализаций).
- Создаёт экземпляр нейросети NAFNet и проводит **smoke-тест** (один шаг прямого и обратного распространения) для проверки градиентов и совместимости с GPU.

Скрипт **не запускает обучение** – он лишь готовит данные и проверяет, что окружение работает. Основное обучение производится скриптом `run_training.py`.

## 2. Ключи командной строки

| Ключ | Тип | Обязательный | Описание |
|------|-----|--------------|-----------|
| `-opt PATH` | строка | **Да** | Путь к конфигурационному YAML-файлу (например, `options/train/RAW_NAFNet_NikonD600.yml`). |
| `--clean` | флаг | Нет | **Устаревший**. Очищает и датасет, и визуализации (эквивалентно `--clean-dataset --clean-visuals`). |
| `--clean-dataset` | флаг | Нет | Удаляет папки `train/` и `test/` внутри `dataset_root` (датасет перегенерируется). |
| `--clean-visuals` | флаг | Нет | Удаляет старые файлы визуализации (папка `visuals_logger.output_dir`). |
| `--clean-training` | флаг | Нет | Не используется в `run_pipeline.py` (применяется в `run_training.py`). |
| `--resume` | строка | Нет | Не используется в `run_pipeline.py` (передаётся в `run_training.py`). |

**Пример запуска:**  
```bash
./run_pipeline.py -opt options/train/RAW_NAFNet_NikonD600.yml --clean-dataset
```

## 3. Конфигурационный YAML-файл

`run_pipeline.py` использует те же секции YAML, что и `run_training.py`, но считывает только определённые из них. Ниже приведены секции, которые влияют на работу `run_pipeline.py`, и их ключи.

### 3.1. Общие настройки

| Ключ | Назначение | Пример |
|------|------------|--------|
| `name` | Имя эксперимента (используется для подстановки в пути, если включено). | `RAW-NAFNet-D600` |

### 3.2. Секция `path`

| Ключ | Назначение | Пример |
|------|------------|--------|
| `source_images_dir` | Папка с исходными эталонными изображениями (HQ) для генерации датасета. | `"/home/grand/Images/NEF_Test"` |
| `dataset_root` | Корневая папка, куда будет сохранён сгенерированный датасет (подпапки `train/`, `test/`). | `"datasets/nef_nafnet"` |

### 3.3. Секция `process_data`

Параметры физической деградации (используются модулем `pipeline_generation_core.py` при генерации датасета).

| Ключ | Назначение | Пример |
|------|------------|--------|
| `downscale_factor` | Коэффициент уменьшения разрешения (имитация мелкого сенсора). | `4` |
| `noise.add` | Добавлять ли шум. | `true` |
| `noise.snr_db` | Отношение сигнал/шум (дБ). | `20` |
| `noise.correlated` | Использовать коррелированный шум (свёртка с ЧКХ). | `true` |
| `noise.psf_sigma` | Параметр размытия (сигма гауссианы) для PSF. | `1.5` |

### 3.4. Секция `network_g`

Параметры архитектуры NAFNet (используются для создания модели в smoke-тесте).

| Ключ | Назначение | Пример |
|------|------------|--------|
| `num_in_ch` | Число входных каналов (должно быть 4 для RGGB). | `4` |
| `num_out_ch` | Число выходных каналов (обычно 3 для RGB). | `3` |
| `width` | Базовая ширина каналов. | `32` |
| `enc_blk_nums` | Количество блоков на этапах энкодера. | `[2,2,4,8]` |
| `middle_blk_num` | Количество блоков в латентном пространстве. | `12` |
| `dec_blk_nums` | Количество блоков на этапах декодера. | `[2,2,2,2]` |

### 3.5. Секция `visuals_logger`

Настройки визуального контроля.

| Ключ | Назначение | Пример |
|------|------------|--------|
| `output_dir` | Папка для сохранения превью LQ и HQ. Поддерживает подстановку `{name}`. | `"experiments/{name}/debug_visuals"` |
| `lq_preview_name` | Имя файла для LQ-превью (после демозаики). | `"debug_lq_preview.png"` |
| `gt_reference_name` | Имя файла для HQ-эталона. | `"debug_gt_reference.png"` |

### 3.6. Секция `pipeline_logger`

Настройки общего логгера (сообщения, предупреждения, ошибки).

| Ключ | Назначение | Пример |
|------|------------|--------|
| `log_file` | Путь к файлу лога. Поддерживает подстановку `{name}`. | `"experiments/{name}/pipeline.log"` |

### 3.7. Прочие секции, не используемые `run_pipeline.py`

- `datasets` (кроме `gt_size`, который может использоваться в `RestorationDataset` для визуализации, но в `run_pipeline.py` не критичен).
- `train` (гиперпараметры обучения – не нужны).
- `logger` (настройки логирования обучения – не используются).
- `losses` – не используются.

## 4. Что генерирует скрипт и куда сохраняет

### 4.1. Генерация датасета

Если датасет пуст или был запрошена очистка (`--clean-dataset`), скрипт запускает внутреннюю генерацию (через `pipeline_prepare.ensure_dataset_ready`). Процесс:

1. Читает исходные изображения из `path.source_images_dir`.
2. Для каждого изображения последовательно применяет:
   - Пространственное сжатие (`downscale_factor`).
   - Свёртку с PSF (гауссиана, `psf_sigma`).
   - Наложение маски Байера (RGGB).
   - Добавление шума (коррелированного или нет).
   - Извлечение 4 подканалов (R, G1, G2, B).
3. Сохраняет:
   - **LQ** – 4-канальный 16-битный TIFF в `dataset_root/train/lq_inputs/` (или `test/lq_inputs/`).
   - **HQ** – RGB PNG (после сжатия и PSF, но без шума и мозаики) в `dataset_root/train/hq_targets/` (или `test/hq_targets/`).

Разбиение на train/test выполняется согласно `train_ratio = 0.95` (фиксировано в коде, можно изменить в YAML).

### 4.2. Визуальный контроль

После загрузки датасета (или его генерации) скрипт сохраняет случайный LQ и соответствующий HQ в папку `visuals_logger.output_dir`. LQ-изображение предварительно обрабатывается билинейной демозаикой, чтобы получить читаемое RGB-превью.

### 4.3. Smoke-тест

Создаётся модель NAFNet с параметрами из `network_g`, на первом сэмпле датасета выполняется один прямой и обратный проход с комбинированным лоссом (L1 + FFL). Проверяется, что градиенты вычисляются и оптимизатор работает.

### 4.4. Где искать результаты

| Тип данных | Путь (по умолчанию) |
|------------|----------------------|
| Сгенерированный датасет (LQ) | `dataset_root/train/lq_inputs/` и `dataset_root/test/lq_inputs/` |
| Сгенерированный датасет (HQ) | `dataset_root/train/hq_targets/` и `dataset_root/test/hq_targets/` |
| Превью визуального контроля | `visuals_logger.output_dir` (например, `experiments/RAW-NAFNet-D600/debug_visuals/`) |
| Общий лог (pipeline.log) | `pipeline_logger.log_file` (например, `experiments/RAW-NAFNet-D600/pipeline.log`) |

## 5. Вывод

`run_pipeline.py` является **инструментом подготовки инфраструктуры** перед обучением. Он гарантирует, что:

- Датасет сгенерирован правильно (физически достоверная деградация).
- Визуально можно убедиться в адекватности пар LQ/HQ.
- Модель и окружение работают (smoke-тест).

После успешного выполнения `run_pipeline.py` можно запускать `run_training.py` для обучения нейросети. Скрипт не требует ручной настройки – все параметры задаются в YAML-конфиге, что обеспечивает воспроизводимость экспериментов.
