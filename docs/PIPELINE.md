# PIPELINE.md – Запуск конвейера обработки изображений (JDSR)

В этом документе описан полный порядок действий для подготовки данных, обучения модели, валидации и оценки качества. Все команды предполагают, что вы находитесь в корневой директории проекта.

---

## 1. Генерация датасета

Перед обучением необходимо создать синтетический датасет из исходных резких изображений (например, NEF‑файлов или любых RGB‑изображений). За это отвечает скрипт `prepare_dataset.py`.

**Команда:**

```bash
python prepare_dataset.py -opt options/training/your_config.yml --clean-dataset
```

- `--clean-dataset` – полностью удаляет старые папки `train/` и `test/` внутри `dataset_root` и генерирует датасет заново.
- Без этого флага генерация выполняется только при отсутствии данных (или если датасет пуст).

**Что происходит:**
- Из каждого исходного изображения в `source_images_dir` вырезается центральный HQ‑патч размера `gt_size` (например, 512×512).
- Применяется физическая деградация: оптическое уменьшение в `downscale_factor` раз, PSF‑размытие, маска Байера (RGGB), добавление шума (если включено), упаковка в 4 субканала.
- Результаты сохраняются:
  - HQ (эталон) → `dataset_root/train/hq_targets/*.png`
  - LQ (упакованный Bayer) → `dataset_root/train/lq_inputs/*_bayer.tiff`
- Аналогично для тестовой выборки (разделение по `train_ratio`, по умолчанию 0.95).

**Проверка:**  
После генерации в `dataset_root/train/lq_inputs` должны быть файлы `.tiff`, в `dataset_root/train/hq_targets` – `.png`. Убедитесь, что размеры LQ и HQ согласованы: `h_hq = upscale_factor * h_lq`.

## 2. Предобученческая верификация (опционально)

Скрипт `run_pipeline.py` выполняет визуальный контроль датасета и smoke‑тест градиентов, не запуская длительное обучение.

**Команда:**

```bash
python run_pipeline.py -opt options/training/your_config.yml
```

**Этапы:**
1. **Генерация датасета** (если ещё не сгенерирован или стоит флаг `--clean-dataset`).
2. **Визуальный контроль** – загружается первый образец из датасета, применяется билинейная демозаика к LQ и сохраняется превью LQ и HQ в `experiments/{name}/debug_visuals/`. Это позволяет убедиться, что деградация выглядит реалистично.
3. **Smoke‑тест** – один прямой и обратный проход с комбинированным лоссом (L1 + FFL) на одном батче. Проверяются градиенты и использование VRAM.

**Результат:** Если всё прошло без ошибок, вы увидите `🎉 ВСЕ ПРОВЕРКИ ПРОЙДЕНЫ УСПЕШНО!`. Это означает, что датасет корректен, модель совместима с устройством и градиенты проходят.

## 3. Обучение модели

Основной скрипт обучения – `run_training.py`. Он загружает датасет, инициализирует модель (с возможностью частичной загрузки предобученных весов), оптимизатор и планировщик, запускает цикл по эпохам.

**Команда:**

```bash
python run_training.py -opt options/training/your_config.yml
```

**Ключевые особенности:**
- **Автоматическое возобновление** – если в `checkpoint_path` (из `path.resume_path`) существует чекпоинт, обучение продолжится с той же эпохи/батча. Флаг `auto_resume: true` в секции `datasets.train` включает это поведение.
- **Прогрев FFL** – параметр `losses.ffl_start_epoch` (например, 20) определяет, с какой эпохи начинает работать Focal Frequency Loss. До этого используется только L1‑лосс.
- **Клиппинг градиентов** – `max_norm=1.0` после `backward()` для стабильности.
- **Валидация** – после каждой эпохи (или с частотой `validation_freq`) запускается валидация на тестовой выборке: вычисляются SSIM и PSNR, сохраняются предсказания в `experiments/{name}/val_predictions/`.
- **Логирование** – метрики пишутся в:
  - `train_metrics.csv` – шаг, loss, psnr, lr, delta_psnr, grad_var, tv_ratio, VRAM, l1_loss, ffl_loss.
  - `val_metrics.csv` – эпоха, ssim, psnr.
  - `train_progress.log` – текстовый лог с выбранными полями.
  - TensorBoard (опционально, если `logger.use_tb_logger: true`).
- **Сохранение чекпоинтов** – каждые `save_checkpoint_epoch` эпох. При аварийном завершении (Ctrl+C) сохраняется флаг `is_emergency`, что позволяет продолжить с точного места.

**Пример ожидаемого вывода в консоли:**
```
[RAW-NAFNet-Final-100] Epoch 0/300 Batch 10/250 Loss: 0.12345 PSNR: 22.34 dB VRAM: 4.52GB
...
📊 [Валидация] Итог эпохи 0 — Средний PSNR: 23.10 dB, Средний SSIM: 0.8542
```

## 4. Оценка baseline (классические методы демозаики)

Для сравнения с традиционными подходами используется `evaluate_baseline.py`. Он применяет билинейную и MHC демозаику к тестовым LQ и вычисляет средние PSNR/SSIM.

**Команда:**

```bash
python evaluate_baseline.py -opt options/training/your_config.yml
```

**Результат:** в логе появятся строки вида:
```
=== BASELINE SUMMARY ===
Bilinear  -> Mean PSNR = 34.61 dB, Mean SSIM = 0.9640
MHC       -> Mean PSNR = 36.22 dB, Mean SSIM = 0.9720
```

Эти значения служат нижней границей для нейросетевого метода.

## 5. Построение графиков

Для визуализации истории обучения используется `plot_metrics.py`, который читает CSV‑файлы и генерирует графики в соответствии с конфигурацией (обычно `plot_metrics.yml`).

**Команда:**

```bash
python plot_metrics.py -opt options/training/plot_metrics.yml
```

**Что можно построить:**
- Кривую лосса (loss vs step)
- PSNR на обучении (psnr vs step)
- График learning rate (lr vs step)
- Сравнение PSNR модели с baseline (линия сравнения)
- SSIM на валидации (epoch vs ssim)
- Дополнительные метрики (delta_psnr, grad_var, tv_ratio)

Все графики сохраняются в папку, указанную в `output_dir` (например, `experiments/{name}/figures/`).

## 6. Инференс на видео (опционально)

Если обученная модель применяется к видео, используется скрипт `process_video.py`.

**Команда:**

```bash
python process_video.py --input input.mp4 --output output.mp4 --config options/training/your_config.yml --checkpoint experiments/RAW-NAFNet-Final-100/checkpoints/resume_nef_nafnet_100.pth
```

- Каждый кадр обрабатывается через ту же функцию деградации (опционально) и затем через модель.
- Результат сохраняется как MP4‑файл.

Подробности реализации см. в `video_inference.py` и `video_degradation.py`.

## 7. Важные замечания по конфигурации

- **Масштабирование:**  
  Параметры `process_data.downscale_factor` (оптическое уменьшение) и `network_g.upscale_factor` (восстановление) должны удовлетворять соотношению:  
  `upscale_factor = downscale_factor × 2`.  
  Например, `downscale_factor=2` → `upscale_factor=4`.

- **Размеры патчей:**  
  `gt_size` (размер HQ) должен строго равняться `upscale_factor × lq_size`. Например, `gt_size=512`, `upscale_factor=4` → `lq_size=128`. Несоблюдение вызовет `assert` в датасете.

- **Шум:**  
  При `noise.add: true` моделируется коррелированный (если `correlated: true`) или некоррелированный шум с заданным SNR.

- **Аугментации:**  
  Для сохранения топологии RGGB используются только отражения (`use_flip: true`). Повороты на 90° отключены.

- **Предобученные веса:**  
  Если указан `path.pretrain_network_g`, модель попытается загрузить веса из SIDD-модели NAFNet. Несовместимые слои (входной/выходной) будут проигнорированы, внутренние слои перенесены.

## 8. Типичный порядок работы (краткий чек-лист)

1. **Подготовить исходные изображения** – положить их в папку, указанную в `source_images_dir`.
2. **Настроить конфиг** (`your_config.yml`) – задать пути, параметры деградации, размеры патчей, гиперпараметры обучения.
3. **Сгенерировать датасет** – `prepare_dataset.py -opt your_config.yml --clean-dataset`.
4. **(Опционально) Визуально проверить** – `run_pipeline.py -opt your_config.yml`.
5. **Запустить обучение** – `run_training.py -opt your_config.yml`.
6. **Оценить baseline** – `evaluate_baseline.py -opt your_config.yml`.
7. **Построить графики** – `plot_metrics.py -opt plot_metrics.yml`.
8. **Применить модель к видео** – `process_video.py ...`.
