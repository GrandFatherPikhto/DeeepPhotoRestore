## `run_pipeline.py`

### 1. Что должен делать `run_pipeline.py` согласно исходному техническому заданию (эксперименту диплома)

Согласно ТЗ магистерской диссертации, `run_pipeline.py` является **главным проверочным конвейером**, который должен:

- **Проверить наличие готового обучающего датасета** (пар `LQ`/`HQ`), сгенерированного в соответствии с физической моделью деградации:  
  `эталон RGB → downscale → PSF (ЧКХ) → маска Байера → коррелированный шум → извлечение 4 каналов RGGB → сохранение 16‑битных TIFF`.
- **При отсутствии или очистке датасета – запустить генерацию** (синхронно, без внешних скриптов).
- **Загрузить датасет** через кастомный `RestorationDataset` (с кропом/ресайзом до $256\times256$ и аугментацией: повороты на $90^\circ$, отражения).
- **Выполнить визуальный контроль** – сохранить примеры `LQ` и `HQ` превью для ручной верификации.
- **Провести smoke-тест нейросети NAFNet** – прямой и обратный проход, расчёт комбинированного лосса ($L_1 + \gamma\cdot\text{FFL}$), проверка градиентов.
- **Завершиться с кодом ошибки при любом сбое**, логгируя все шаги.

### 2. Что он делает (текущая реализация после рефакторинга)

`run_pipeline.py` в текущей версии полностью реализует перечисленные требования:

- **Парсит аргументы** (`-opt`, `--clean-dataset`, `--clean-visuals`), загружает YAML-конфиг.
- **Определяет устройство** (GPU/CPU) через `pipeline_device.get_torch_device()`.
- **Вызывает `ensure_dataset_ready()`** из `pipeline_prepare.py`, которая:
  - очищает папки `train/` и `test/` при флаге `--clean-dataset`;
  - проверяет пустоту датасета;
  - при пустоте напрямую запускает `process_source_images()` (генерация без `subprocess`).
- **Создаёт датасет** через `pipeline_data.create_restoration_dataset()` – загружает пары `*_bayer.tiff` (4-канальный 16‑бит) и соответствующие `*.png` (RGB), применяет `_resize_to_gt` (256×256) и аугментацию (группа $D_4$).
- **Запускает визуальный контроль** (`pipeline_visuals.run_visual_control`) – удаляет старые превью при `--clean-visuals` и сохраняет новые `debug_lq_preview.png`, `debug_gt_reference.png`.
- **Инициализирует модель NAFNet** через `pipeline_model.create_nafnet_model()` с параметрами из конфига.
- **Проводит smoke-тест** (`pipeline_smoke.run_smoke_test`) – один шаг оптимизации с комбинированной потерей (`L1Loss` + `FocalFrequencyLoss`).
- **Логирует каждый шаг** и перехватывает исключения, аварийно завершаясь с кодом `1`.

### 3. Итог

- **`run_pipeline.py` полностью соответствует ТЗ эксперимента** – он проверяет/генерирует физически достоверный датасет, загружает данные, визуально контролирует их, тестирует градиенты модели и комбинированный лосс.
- **Рефакторинг завершён**: весь код разбит на библиотеки `libraries/pipeline_*.py` (каждая ≤100 строк), устранены дублирования и `subprocess`, добавлена прямая генерация.
- **Флаги разделены**: `--clean-dataset` (перегенерация данных), `--clean-visuals` (очистка превью).
- **Восстановлена физическая модель деградации** (downscale → PSF → Байер → коррелированный шум) в модулях `pipeline_generation_*`.
- **Конвейер готов к запуску обучения** (`run_training.py`), так как все предварительные проверки проходятся успешно.
