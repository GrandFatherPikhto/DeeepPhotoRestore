# Интеграция масштабов деградации и восстановления (downscale / upscale)

В данном комплексе реализована **сквозная схема совместной демозаики и суперразрешения** (Joint Demosaicing and Super-Resolution). Это означает, что общее геометрическое сжатие от исходного RGB-изображения (HQ) до упакованного Bayer-пакета (LQ) складывается из двух независимых факторов:

1. **Оптическое уменьшение** (симуляция ограниченного разрешения объектива) – параметр `downscale_factor`.
2. **Субдискретизация, присущая маске Байера** – всегда уменьшает размер в 2 раза (т.к. каждый цветовой канал прореживается).

Модель NAFNet получает на вход LQ размера `(H_lq, W_lq, 4)` и должна восстановить HQ размера `(H_hq, W_hq, 3)`. Для этого в архитектуру добавлен слой `PixelShuffle` с коэффициентом `upscale_factor`.

---

## 1. Формула общего сжатия

Общий коэффициент линейного уменьшения от HQ до LQ:

```
S = downscale_factor × 2
```

- Если `downscale_factor = 1` (оптического уменьшения нет), то `S = 2` – сжатие только за счёт мозаики Байера.
- Если `downscale_factor = 2` (оптическое уменьшение в 2 раза), то `S = 4`.
- Если `downscale_factor = 4` – то `S = 8`, и т.д.

Следовательно, размеры LQ и HQ связаны соотношением:

```
H_hq = S × H_lq      (и аналогично для ширины)
W_hq = S × W_lq
```

---

## 2. Восстановление моделью

Модель `NAFNetDemosaicSuperResolutionWrapper` использует `PixelShuffle(upscale_factor)`. Этот слой преобразует тензор формы `(B, C_in, H_lq, W_lq)` в `(B, C_out, H_lq×k, W_lq×k)`, где `k = upscale_factor`, а `C_out = C_in // k²`.

Чтобы модель могла восстановить исходный размер HQ, необходимо:

```
upscale_factor = S = downscale_factor × 2
```

Только при этом условии выходной тензор модели будет в точности совпадать по размерам с HQ-патчем.

---

## 3. Согласование размеров патчей в датасете

В конфигурационном файле задаются два ключевых параметра:

- `datasets.train.gt_size` – размер квадратного HQ-патча (например, 512 пикселей).
- `datasets.train.lq_size` – ожидаемый размер квадратного LQ-патча (количество пикселей по каждой стороне, **до упаковки 4 каналов**).

**Жёсткое условие** (проверяется через `assert` в `CustomNEFPairDataset`):

```python
assert gt_size == upscale_factor * lq_size
```

Это гарантирует, что загружаемые из датасета LQ и HQ пары имеют правильное геометрическое соотношение.

---

## 4. Автоматический расчёт реального размера LQ при генерации

В модуле `pipeline_generation_core.py` функция `generate_lq_from_hq` **не использует** `lq_size` из конфига. Вместо этого она вычисляет реальный размер LQ на лету по формуле:

```python
lq_packed_size = gt_size // downscale_factor // 2
```

Поэтому при настройке эксперимента **важно синхронизировать** значение `lq_size` в YAML с этой формулой. В противном случае `assert` в датасете упадёт, так как реальные данные будут иметь другой размер.

## 5. Примеры конфигураций

В таблице приведены проверенные сочетания параметров, которые дают физически корректную работу всего конвейера.

| downscale_factor | upscale_factor (S) | gt_size | lq_size = gt_size // S | Комментарий |
|----------------|-------------------|---------|------------------------|-------------|
| 1              | 2                 | 256     | 128                    | Базовый вариант (только демозаика) |
| 1              | 2                 | 512     | 256                    | Более крупные патчи (больше контекста) |
| 2              | 4                 | 512     | 128                    | **Рекомендуемый** для JDSR |
| 2              | 4                 | 1024    | 256                    | Для высокодетальных сцен (требует много VRAM) |
| 4              | 8                 | 1024    | 128                    | Экстремальное сжатие (для исследования пределов) |

---

## 6. Практические рекомендации

### ✅ При выборе параметров

- **Используйте `downscale_factor = 2` как компромисс** между реалистичностью (учитывается ограниченная оптика) и вычислительной эффективностью.
- **Всегда устанавливайте `upscale_factor = downscale_factor × 2`**.
- **Подбирайте `gt_size` так, чтобы `lq_size` был не менее 64–128** – иначе в LQ останется слишком мало пространственной информации.
- **Следите за VRAM**: увеличение `gt_size` в 2 раза увеличивает площадь в 4 раза → память и время обучения растут квадратично.

### ❌ Чего избегать

- Не используйте `upscale_factor = 2` при `downscale_factor > 1` – тогда выход модели будет в `downscale_factor` раз меньше HQ, и датасет аварийно завершится с `assert`.
- Не указывайте в конфиге произвольный `lq_size`, не согласованный с формулой – это приведёт к ошибке размерностей.
- Не меняйте `downscale_factor` после генерации датасета – иначе LQ и HQ перестанут соответствовать друг другу (перегенерируйте датасет с флагом `--clean-dataset`).

## 7. Проверка правильности настройки

После генерации датасета и перед запуском обучения можно выполнить быструю проверку:

```bash
python -c "
from libraries.training_dataset_nef import CustomNEFPairDataset
from libraries.config import get_pipeline_config

opt = get_pipeline_config()
dataset = CustomNEFPairDataset(
    opt['path']['dataset_root'] + '/train/lq_inputs',
    opt['path']['dataset_root'] + '/train/hq_targets',
    opt=opt
)
lq, hq = dataset[0]
print(f'LQ shape: {lq.shape}')   # должно быть (4, lq_size, lq_size)
print(f'HQ shape: {hq.shape}')   # должно быть (3, gt_size, gt_size)
print(f'Соотношение: {hq.shape[1]} / {lq.shape[1]} = {hq.shape[1] / lq.shape[1]}')
# Ожидается: upscale_factor
"
```

Если вывод показывает правильное соотношение, значит настройки выполнены корректно.

## 9. Резюме

Для стабильной работы конвейера достаточно запомнить одно правило:

> **`upscale_factor = downscale_factor × 2`**  
> **`lq_size = gt_size // upscale_factor`**

Все остальные значения вычисляются автоматически. Придерживаясь этого, вы гарантированно получите физически корректную постановку задачи Joint Demosaicing and Super-Resolution.
