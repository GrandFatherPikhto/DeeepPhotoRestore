# ALGORITHM.md – Алгоритмы обработки изображений в комплексе DeepPhotoRestore

В данном документе описываются основные алгоритмы, используемые в конвейере восстановления RAW-изображений (демозаика, суперразрешение, симуляция деградации, функция потерь).

---

## 1. Физическая модель деградации (генерация LQ)

Цель: из исходного RGB-изображения высокого качества (HQ) получить реалистичный низкокачественный RAW-пакет (LQ), имитирующий съёмку на цифровую камеру.

### 1.1. Центральный кроп с фазовым выравниванием

Из HQ вырезается квадратный патч размера `gt_size` (например, 512×512) с центром изображения. Координаты кропа корректируются так, чтобы быть кратными 4, что сохраняет целостность фазы RGGB-сетки после последующих уменьшений.

### 1.2. Оптическое уменьшение (downscale)

Патч уменьшается в `downscale_factor` раз (обычно 2) с помощью билинейной интерполяции (OpenCV `INTER_LINEAR`). Это моделирует ограниченную разрешающую способность объектива.

### 1.3. Размытие пятном рассеяния (PSF)

Свёртка с гауссовым ядром (сигма `psf_sigma` ≈ 0.5…1.5) имитирует аберрации оптической системы.

### 1.4. Наложение маски Байера (RGGB)

Для каждого пикселя сохраняется только один цветовой канал в соответствии с паттерном:

```
R G
G B
```

Результат – одноканальное изображение `bayer_float` в диапазоне [0,1].

### 1.5. Аддитивный шум

- **Некоррелированный (белый) гауссов шум:** добавляется непосредственно к `bayer_float` с заданным SNR (дБ).
- **Коррелированный шум:** сначала генерируется белый шум, затем он свёртывается с ядром PSF, что имитирует шум, сглаженный оптической системой.

### 1.6. Упаковка в 4 подканала (RGGB)

Из одноканальной мозаики извлекаются четыре субдискретизированных канала:

- Канал 0: R (чётные строки, чётные столбцы)
- Канал 1: G1 (чётные строки, нечётные столбцы)
- Канал 2: G2 (нечётные строки, чётные столбцы)
- Канал 3: B (нечётные строки, нечётные столбцы)

Итоговый LQ имеет размер `(gt_size // downscale_factor // 2) × (gt_size // downscale_factor // 2) × 4`.

**Общий коэффициент сжатия:** `S = downscale_factor × 2`. Восстановление требует `upscale_factor = S`.

## 2. Демозаика (базовые методы)

Используются для сравнения в `evaluate_baseline.py`.

### 2.1. Билинейная демозаика

Каждый из четырёх каналов (R, G1, G2, B) увеличивается в 2 раза с помощью билинейной интерполяции (`scipy.ndimage.zoom`, order=1). Затем два зелёных канала усредняются, и каналы объединяются в RGB.

### 2.2. Алгоритм Malvar‑He‑Cutler (MHC)

Классический метод демозаики, использующий градиентно-ориентированную интерполяцию:

1. Восстанавливается полноразмерная мозаика Bayer (2H×2W) из упакованных каналов.
2. **Интерполяция зелёного канала** в позициях R и B с помощью ядра 5×5, учитывающего лапласиан второго порядка.
3. **Интерполяция красного и синего каналов** с коррекцией по разности с зелёным каналом, что подавляет цветовые артефакты.

Реализация в проекте следует оригинальной статье [Malvar, He, Cutler, 2004].

## 3. Нейросетевая архитектура NAFNet (адаптированная)

### 3.1. Базовая сеть

Используется сеть **NAFNet** (Nonlinear Activation Free Network) из репозитория `basicsr`. Её ключевая особенность – замена нелинейных активаций (ReLU, GELU) на простые масштабирующие операции (SCALE), что снижает вычислительную нагрузку при сохранении качества.

### 3.2. Модификация для демозаики + суперразрешения

Оригинальный NAFNet работает с 3 цветовыми каналами. Мы адаптируем его для задачи Joint Demosaicing and Super-Resolution:

1. **Входной адаптер:** 4 канала (RGGB) → промежуточные каналы → `PixelShuffle(upscale_factor)` → RGB пространство высокого разрешения.
2. **Глубокая сеть NAFNet** работает уже в полном разрешении (например, 512×512), обрабатывая RGB-изображение, но с внутренним числом каналов 4 (чтобы использовать предобученные веса SIDD).
3. **Выходной адаптер:** преобразование из 4 внутренних каналов обратно в 3 RGB.

Таким образом, все блоки NAFNet участвуют в восстановлении высокочастотных деталей, а не только финальные слои.

### 3.3. Загрузка предобученных весов (Partial Weight Transfer)

При наличии предобученной модели SIDD (шумоподавление) веса загружаются частично: слои `intro` и `ending`, имеющие несовместимую размерность, игнорируются, а все совместимые слои (661 внутренний слой) переносятся. Это даёт значительный выигрыш в скорости сходимости.

## 4. Функция потерь

### 4.1. L1 Loss (пространственный)

Обычная L1-норма между предсказанным RGB и эталоном:

```
L1 = mean(|pred - target|)
```

Обеспечивает базовую точность пикселей.

### 4.2. Focal Frequency Loss (FFL) – спектральный

Частотная потеря, фокусирующаяся на амплитудных спектрах:

- Выполняется 2D БПФ для `pred` и `target`.
- Амплитуды преобразуются в логарифмическую шкалу (опционально) для баланса низких и высоких частот.
- Вычисляется взвешенная квадратичная ошибка амплитуд с фокальным весом: чем больше ошибка на данной частоте, тем выше её вклад.
- Итоговая потеря: `FFL = mean(weight * distance²) * loss_weight`.

FFL помогает восстанавливать мелкие текстуры и подавлять муар, который L1 пропускает.

### 4.3. Комбинированная потеря

```
total = l1_weight * L1 + ffl_weight * FFL
```

С параметрами `l1_weight = 1.5`, `ffl_weight = 0.2` (эмпирически подобранный баланс).

### 4.4. Прогрев FFL

Первые `ffl_start_epoch` (обычно 20) эпох `ffl_weight` эффективно равен 0 – сеть обучается только на L1. Затем FFL автоматически активируется. Это предотвращает градиентные всплески на начальном этапе, когда `PixelShuffle` ещё не адаптирован.

## 5. Цикл обучения

- Оптимизатор: AdamW (`lr = 1e-4`, `weight_decay = 1e-4`).
- Планировщик: MultiStepLR, снижение `lr` в 10 раз на эпохах `milestones` (например, 150 и 225).
- Клиппинг градиентов: `max_norm = 1.0`.
- Валидация: каждую эпоху вычисляются PSNR и SSIM на тестовом наборе (центрированные кропы с учётом `upscale_factor`).
- Логирование: CSV-файлы (`train_metrics.csv`, `val_metrics.csv`), текстовый лог, опционально TensorBoard.

---

## 6. Валидация (метрики)

### 6.1. PSNR (Peak Signal-to-Noise Ratio)

Вычисляется для каждого тестового патча в пространстве `uint8` [0, 255]:

```
MSE = mean((pred - gt)²)
PSNR = 20 * log10(255 / sqrt(MSE))
```

### 6.2. SSIM (Structural Similarity Index)

Используется реализация из `skimage.metrics.structural_similarity` с канальным усреднением (`channel_axis=2`).

## 7. Аугментации

Для увеличения разнообразия данных и предотвращения переобучения используются только зеркальные отражения (horizontal / vertical flip). Повороты на 90° исключены, так как они нарушают порядок подканалов RGGB.

## 8. Основные конфигурационные параметры

| Параметр | Значение по умолчанию | Смысл |
|----------|----------------------|-------|
| `process_data.downscale_factor` | 2 | Оптическое уменьшение |
| `network_g.upscale_factor` | 4 | Восстанавливаемый масштаб (должен = downscale_factor×2) |
| `datasets.train.gt_size` | 512 | Размер HQ-патча |
| `datasets.train.lq_size` | 128 | Размер LQ-патча ( = gt_size // upscale_factor ) |
| `losses.ffl_start_epoch` | 20 | Эпоха включения FFL |
| `train.num_epochs` | 300 | Общее количество эпох |
| `train.optim_g.lr` | 1e-4 | Начальная скорость обучения |
