# Полный алгоритм работы пайплайна восстановления изображений (демозаика + супер-разрешение)

## 1. Общая схема

Проект решает задачу преобразования **шумного, размытого Байеровского RAW** (упакованного в 4 субканала RGGB) в **резкое полноцветное RGB-изображение** с увеличением разрешения в 2 раза.  
Алгоритм состоит из трёх основных фаз:

1. **Генерация синтетического датасета** (из исходных резких изображений создаются пары «LQ – шумный упакованный RAW» / «HQ – резкое RGB»).
2. **Обучение модели** (NAFNet + PixelShuffle) с комбинированной потерей L1 + Focal Frequency Loss.
3. **Инференс** (применение обученной модели к новым RAW-файлам или видео).

Ниже каждый этап описан детально.

---

## 2. Генерация датасета

### 2.1 Входные данные

- Папка `source_images` содержит исходные **резкие** изображения в любом формате (PNG, JPEG, TIFF, NEF, CR2 и т.д.).  
- Поддерживаются как 8‑битные, так и 16‑битные изображения.  
- Все исходные изображения приводятся к 8‑битному RGB (если нужно) с помощью функции `load_rgb`.

### 2.2 Параметры деградации (из YAML-конфига)

- `downscale_factor` – во сколько раз уменьшить разрешение перед формированием LQ (обычно 1).  
- `psf_sigma` – параметр размытия (Гауссово ядро) для моделирования ЧКХ объектива.  
- `add_noise` – включать/выключать шум.  
- `snr_db` – отношение сигнал/шум в децибелах.  
- `correlated` – коррелированный (свёрнутый с PSF) или некоррелированный шум.

### 2.3 Шаги генерации одной пары (функция `generate_lq_from_hq`)

1. **Таргет (HQ)** – исходное резкое RGB-изображение без изменений. Сохраняется как `PNG` в папку `hq_targets`.

2. **Подготовка изображения для LQ**:  
   - Если `downscale_factor > 1`, изображение уменьшается в заданное количество раз (билинейная интерполяция).  
   - Результат (`hq_small`) переводится в `float32` в диапазоне `[0,1]`.

3. **Размытие (PSF)**:  
   - Создаётся Гауссово ядро `create_psf_kernel(sigma, size=15)` с нормировкой суммы = 1.  
   - Каждый цветовой канал `hq_small` свёртывается с этим ядром (`cv2.filter2D`).  
   - Получается размытое изображение `hq_blurred_float`.

4. **Наложение маски Байера (паттерн RGGB)**:  
   - Функция `apply_bayer_mask_float` из размытого RGB создаёт **одноканальный** массив `bayer_float` размером `(H_small, W_small)`, где пиксели расположены по правилу:  
     * чётная строка, чётный столбец → красный (R)  
     * чётная строка, нечётный столбец → зелёный G1  
     * нечётная строка, чётный столбец → зелёный G2  
     * нечётная строка, нечётный столбец → синий (B)  

5. **Добавление шума (опционально)**:  
   - Вычисляется мощность сигнала `signal_power = mean(bayer_float²)`.  
   - Мощность шума: `noise_power = signal_power / (10^(snr_db/10))`.  
   - Генерируется белый гауссовский шум с нулевым средним и дисперсией `noise_power`.  
   - Для **коррелированного** шума белый шум свёртывается с тем же PSF-ядром.  
   - Шум добавляется к `bayer_float` (попиксельно), результат клиппируется в `[0,1]`.  
   - **Важно:** шум добавляется **после** маски Байера – это физически корректно (шумится уже отфильтрованный пиксель).

6. **Упаковка в 4 канала**:  
   - `bayer_float` масштабируется в 16‑битный диапазон: `bayer_16bit = bayer_float * 65535`.  
   - Функция `extract_bayer_subchannels` из массива `(H_small, W_small)` формирует **4‑канальный** тензор `(H_small/2, W_small/2, 4)`, где:  
     * канал 0: R – все пиксели с позиций (чёт, чёт)  
     * канал 1: G1 – (чёт, нечёт)  
     * канал 2: G2 – (нечёт, чёт)  
     * канал 3: B – (нечёт, нечёт)  
   - Это и есть вход для нейросети (`lq_packed`). Размер по высоте и ширине стал вдвое меньше исходного `hq_small`.

7. **Сохранение**:  
   - `lq_packed` сохраняется как 16‑битный TIFF (`*_bayer.tiff`).  
   - `hq_target` (резкое RGB) сохраняется как PNG.

### 2.4 Разделение на train / test

- Все исходные файлы перемешиваются с фиксированным `seed`.  
- Доля `train_ratio` (обычно 0.95) идёт в обучающую выборку, остальное – в тестовую.  
- Структура папок:  
  ```
  dataset_root/
    train/
      lq_inputs/      # *_bayer.tiff
      hq_targets/     # *.png
    test/
      lq_inputs/
      hq_targets/
  ```

## 3. Датасет и аугментации (класс `CustomNEFPairDataset`)

### 3.1 Загрузка пары

- По индексу определяется базовое имя файла.  
- LQ загружается из `lq_inputs/*_bayer.tiff` → преобразуется в `float32`, делится на 65535 → получаем `(H_lq, W_lq, 4)` в диапазоне `[0,1]`.  
- HQ загружается из `hq_targets/*.png` → преобразуется в `float32`, делится на 255 → получаем `(H_hq, W_hq, 3)` в `[0,1]`.  
- Проверяется, что `H_hq == 2 * H_lq` и `W_hq == 2 * W_lq`. Если нет – выполняется принудительный ресайз HQ (только для защиты).

### 3.2 Случайный кроп

- Из LQ вырезается квадрат размера `lq_size × lq_size` (случайные координаты).  
- Из HQ вырезается соответствующий квадрат размера `gt_size × gt_size`, где `gt_size = 2 * lq_size`. Координаты угла: `top_hq = top_lq * 2`, `left_hq = left_lq * 2`.  
- Таким образом сохраняется попиксельное соответствие (каждый пиксель LQ соответствует блоку 2×2 в HQ).

### 3.3 Аугментации (синхронные)

- **Отражения:** с вероятностью 50% горизонтальное отражение (`torchvision.transforms.functional.hflip`) применяется одновременно к LQ и HQ. Аналогично для вертикального.  
- **Повороты:** случайное целое число `k` от 0 до 3; если `k > 0`, тензоры поворачиваются на `k * 90` градусов (`TF.rotate`).  
- Аугментации управляются флагами `use_flip` и `use_rot` в YAML.

### 3.4 Выход датасета

- LQ-тензор: `(4, lq_size, lq_size)`  
- HQ-тензор: `(3, gt_size, gt_size)`  
- Оба – `torch.float32` в диапазоне `[0,1]`.

## 4. Архитектура модели (NAFNet + PixelShuffle)

### 4.1 Базовый NAFNet (modified)

- Используется реализация из `basicsr.models.archs.NAFNet_arch`.  
- Входные и выходные каналы базовой сети = `num_in_ch` (по умолчанию 4).  
- Параметры: `width` (32), `middle_blk_num` (12), `enc_blk_nums` ([2,2,4,8]), `dec_blk_nums` ([2,2,2,2]).  
- NAFNet не содержит нелинейных активаций (использует умножение элементов – SimpleGate), что экономит вычисления и память.

### 4.2 Обёртка `NAFNetDemosaicSuperResolutionWrapper`

- Задача: из 4‑канального латентного представления (размер `H×W`) получить RGB-изображение размера `(2H)×(2W)`.  
- Реализация:  
  - Сначала проходит `self.net(x)` – базовый NAFNet (выход – 4 канала).  
  - Затем блок `upsample_block`:  
    * Свёртка `Conv2d(4, mid_channels, kernel_size=3, padding=1)`, где `mid_channels = out_channels * (upscale_factor)^2 = 3 * 4 = 12`.  
    * `PixelShuffle(upscale_factor=2)` – перестраивает каналы в пространство: из (12, H, W) → (3, 2H, 2W).  
  - Полученный RGB клиппируется по диапазону `[0,1]` (неявно через сигмоиду? Нет, просто тензор, на выходе – линейный). При обучении loss сам ограничивает значения.

### 4.3 Инициализация

- Создаётся `raw_model` (NAFNet с `img_channel=4`).  
- Создаётся обёртка `model = NAFNetDemosaicSuperResolutionWrapper(raw_model)`.  
- Модель переносится на `device` (CUDA/CPU).

## 5. Обучение

### 5.1 Функция потерь

Используется **комбинированная потеря** (тип `combined` в конфиге):

- **L1 Loss** (MAE) между предсказанным RGB и таргетом: `l1 = |pred - target|`.  
- **Focal Frequency Loss (FFL)** – работает в частотной области:  
  1. Вычисляется 2D БПФ для `pred` и `target` (комплексное).  
  2. Берётся амплитуда (модуль) `pred_amp`, `target_amp`.  
  3. Квадрат разности амплитуд: `amp_distance = (pred_amp - target_amp)^2`.  
  4. Фокальный вес: `focal_weight = (amp_distance / max(amp_distance))^alpha`.  
  5. `frequency_loss = mean(focal_weight * amp_distance) * loss_weight`.  
- Итоговая потеря: `total = l1_weight * l1 + ffl_weight * ffl`.  
- Альтернативно может использоваться только L1.

### 5.2 Оптимизатор и планировщик

- **AdamW** с `lr` (например, 1e-4), `weight_decay` (1e-4), `betas=(0.9, 0.999)`.  
- **CosineAnnealingLR** с `T_max = num_epochs`, `eta_min = 1e-7`.

### 5.3 Цикл обучения (один шаг)

1. Загружается батч `(lq, hq)` из `DataLoader`.  
2. `lq`, `hq` переносятся на `device`.  
3. `optimizer.zero_grad()`.  
4. `out = model(lq)`.  
5. Вычисляются `metrics` (total_loss, l1_val, ffl_val, psnr) через `compute_metrics`.  
6. `total_loss.backward()`.  
7. **Клиппинг градиентов**: `torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)`.  
8. `optimizer.step()`.  
9. Логирование:  
   - TensorBoard (loss, PSNR, LR).  
   - CSV-файл (train_metrics.csv).  
   - Текстовый файл (train_progress.log) с расширенными метриками (grad_var, TV_ratio, VRAM).  
   - Консольный вывод (каждые `print_freq` шагов).  
10. `global_step += 1`.

### 5.4 Валидация

- Каждые `validation_freq` эпох вызывается `VisualValidator.run_validation`.  
- Для каждого файла из тестовой папки `lq_inputs`:  
  - LQ загружается, из него вырезается **центральный кроп** размера `lq_size`.  
  - Инференс модели → получаем RGB `(gt_size, gt_size)`.  
  - Из таргета (HQ) вырезается центральный кроп с координатами `top_hq = top_lq * 2` и размером `gt_size`.  
  - Сравнение через **SSIM** (skimage.metrics.structural_similarity).  
- Результаты сохраняются:  
  - Изображения предсказаний в `val_predictions/epoch_{epoch}_*.png`.  
  - Метрики в `val_metrics.csv`.  
  - Лог среднего SSIM.

### 5.5 Сохранение чекпоинтов

- Каждые `save_checkpoint_epoch` эпох:  
  - Сохраняется `checkpoint_path` (например, `experiments/exp_name/checkpoints/latest.pth`).  
  - В словаре: `epoch`, `batch_idx=0`, `is_emergency=False`, `model_state_dict`, `optimizer_state_dict`, `scheduler_state_dict`, `global_step`.  
- При прерывании (KeyboardInterrupt) – аварийное сохранение с `is_emergency=True` и `batch_idx = текущий номер батча`.  
- При возобновлении:  
  - Если `is_emergency=True`, обучение продолжается со следующего батча (`start_batch = saved_batch + 1`).  
  - Если `is_emergency=False`, начинается с нулевого батча следующей эпохи.

### 5.6 Адаптация обучения под маленький датасет

- Если доступно мало изображений, важно использовать аугментации и клиппинг градиентов.  
- Рекомендуемый минимальный размер датасета для обобщения: 500–1000 исходных изображений.

## 6. Инференс на видео (опционально)

### 6.1 Пайплайн обработки одного кадра

1. Кадр из видео (BGR) конвертируется в RGB, нормализуется в `float [0,1]`.  
2. Вызывается `generate_lq_from_hq` (без сохранения, только получение `lq_packed`).  
3. Полученный массив приводится к размеру `target_size × target_size` (через `torchvision.transforms.functional.resize`).  
4. Преобразуется в тензор, добавляется batch-измерение, передаётся на `device`.  
5. Модель вычисляет выход `output`.  
6. `output` преобразуется в BGR-кадр (uint8) и записывается в выходное видео.

## 7. Сравнение с классическими методами (бенчмарк)

Скрипт `evaluate_baseline.py` реализует два алгоритма демозаики:

- **Билинейная интерполяция:** каждый из 4 субканалов (R, G1, G2, B) увеличивается в 2 раза (zoom order=1), затем G1 и G2 усредняются, собирается RGB.  
- **Malvar-He-Cutler (MHC):** градиентная демозаика с 5×5 фильтрами, корректирующая цветовые разности.  

Метрики: PSNR, SSIM. Результаты выводятся в консоль и могут быть использованы как baseline для сравнения с нейросетевым подходом.

## 9. Важные замечания по реализации

- **Округление и типы данных:** Вся генерация деградации выполняется в `float32`, только конечный `lq_packed` сохраняется как `uint16`. Это минимизирует ошибки квантования.  
- **Порядок операций:** маска Байера → шум → упаковка. Изменение порядка привело бы к нефизичным артефактам.  
- **Размеры патчей:** `gt_size` должен быть строго равен `2 * lq_size`, иначе модель не сможет корректно применить PixelShuffle.  
- **Аугментации:** повороты только кратные 90°, чтобы не нарушать структуру Байера. Отражения допустимы.  
- **Клиппинг градиентов:** обязателен при использовании FFL, иначе возможен взрыв градиентов.
