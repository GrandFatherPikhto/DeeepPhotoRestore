# 🛠️ Инженерная часть проекта: установка, настройка и работа в VSCode

Данный раздел описывает создание полного программного пайплайна для решения задачи удаления артефактов JPEG-сжатия с помощью нейросетевой модели NAFNet. Вся работа ведётся в **Visual Studio Code** с подключением к **WSL 2** (Windows Subsystem for Linux). Мы не используем LLM, полагаясь на стандартные инструменты Python и фреймворк BasicSR.

---

## 1. Зачем нужна инженерная часть

Цель — построить воспроизводимый конвейер, который:
- автоматически скачивает и подготавливает высококачественные изображения из RAW-датасета;
- создаёт пары «чистый оригинал – испорченное сжатием изображение»;
- настраивает и запускает обучение нейросети NAFNet на видеокарте RTX 4070 Ti;
- позволяет тестировать обученную модель на любых пользовательских изображениях.

Всё это необходимо для получения экспериментальных данных (метрики PSNR, SSIM, визуальное сравнение), которые войдут в диссертацию.

---

## 2. Выбор окружения: WSL 2 + VSCode

### 2.1 Почему WSL 2

- Полноценная среда Ubuntu (Linux) внутри Windows.
- Родная поддержка CUDA от NVIDIA (видеокарта пробрасывается автоматически).
- Отсутствие проблем с компиляцией C++/CUDA расширений (в отличие от чистой Windows).
- Высокая производительность — 95–98% от нативного Linux.

### 2.2 Установка и настройка WSL 2

В PowerShell (администратор) выполнить:

```powershell
wsl --install
```

После перезагрузки установить дистрибутив Ubuntu 22.04 или 24.04 из Microsoft Store. Запустить Ubuntu, задать имя пользователя и пароль.

Обновить систему:

```bash
sudo apt update && sudo apt upgrade -y
```

### 2.3 Настройка VSCode для работы с WSL

1. Установить Visual Studio Code (обычную версию для Windows).
2. Установить расширение **Remote – WSL** (от Microsoft).
3. Открыть VSCode, нажать `Ctrl+Shift+P`, выбрать `Remote-WSL: New Window`.
4. В открывшемся окне VSCode терминал автоматически будет указывать на Ubuntu в WSL.

Все дальнейшие команды выполняются во встроенном терминале VSCode (Ubuntu).


### 3.4 Установка вспомогательных библиотек

```bash
pip install rawpy pillow numpy opencv-python-headless pandas requests
```

- `rawpy` – чтение RAW-файлов (.NEF, .DNG) и их преобразование в RGB.
- `pillow` – работа с изображениями, создание JPEG-артефактов.
- `numpy` – массивовые операции.
- `opencv-python-headless` – дополнительные функции обработки (без GUI).
- `pandas`, `requests` – для скачивания датасета по CSV-ссылкам.

### 3.5 Клонирование и установка NAFNet

```bash
git clone https://github.com/megvii-research/NAFNet
cd NAFNet
pip install -r requirements.txt
python setup.py develop --no_cuda_ext
```

> **Флаг `--no_cuda_ext`** отключает компиляцию пользовательских CUDA-расширений из исходного кода. Это избавляет от ошибок, связанных с несовместимостью версий компилятора gcc/g++, и не снижает производительность — все основные операции уже оптимизированы в самом PyTorch.

## 5. Данные: откуда берём и как готовим

### 5.1 Выбор датасета – RAISE

Используется датасет **RAISE** (8 156 RAW-снимков высокого разрешения с камер Nikon).  
Скачивается не весь архив, а выборочно по CSV-файлу `RAISE_3.csv`, который содержит прямые ссылки на TIFF- и NEF-файлы.

**Почему RAISE:**  
- Необработанные RAW-данные (нет предварительной обработки).
- Высокая детализация (пейзажи, портреты, текстуры).
- Возможность скачать ровно столько изображений, сколько нужно.

### 5.2 Скрипт `download_and_convert.py`

**Назначение:** автоматически скачать заданное количество RAW-файлов по ссылкам из CSV, конвертировать их в RGB-изображения и сохранить в папку `source_images` в формате JPEG (качество 100, без потерь).

**Как работает:**

1. Читает CSV-файл `RAISE_3.csv`.
2. Для каждой строки выбирает ссылку на TIFF (приоритет) или NEF.
3. Скачивает файл через `requests`.
4. Если файл имеет расширение `.nef` – использует `rawpy` для «проявления» (демозаика + баланс белого по камере).  
   Если `.tiff` – открывает через Pillow.
5. Сохраняет результат как JPEG с качеством 100% в папку `source_images`.
6. Ограничивается переменной `MAX_IMAGES` (для теста ставим 10–20, для полноценного обучения – 3000+).

**Ключевые строки кода:**

```python
with rawpy.imread(io.BytesIO(response.content)) as raw:
    rgb_array = raw.postprocess(use_camera_wb=True)
    img = Image.fromarray(rgb_array)
img.save(dest_jpg_path, "JPEG", quality=100)
```

> **Зачем конвертировать RAW в RGB на этом этапе?**  
> Потому что наша модель NAFNet обучена работать с обычными трёхканальными изображениями. Задача демозаики здесь не исследуется – мы сразу получаем готовое цветное изображение от библиотеки `rawpy`, имитируя работу процессора камеры.

### 5.3 Скрипт `prepare_dataset.py`

**Назначение:** создать из исходных чистых изображений структурированный датасет для обучения и валидации.

**Что делает:**

- Перемешивает все файлы в `source_images`.
- Делит на обучающую (95%) и тестовую (5%) выборки.
- Для каждого файла:
  - Копирует оригинал в `dataset_ready/train/hq_targets` или `test/hq_targets` (сохраняя в PNG для единообразия).
  - Создаёт сжатую JPEG-копию с качеством **15** в соответствующую папку `lq_inputs`.

**Почему PNG для оригиналов:**  
Формат PNG без потерь гарантирует, что «идеальный эталон» не содержит артефактов сжатия, которые могли бы исказить расчёт ошибки (loss) при обучении.

**Почему качество JPEG = 15:**  
Это создаёт сильные блочные артефакты и потерю деталей, что заставляет модель учиться действительно восстанавливать структуру, а не просто сглаживать.

**Код создания пары:**

```python
# оригинал
img.save(hq_path, "PNG")
# сжатая копия
img.save(lq_path, "JPEG", quality=15)
```

После выполнения скрипта папка `dataset_ready` готова к использованию в конфигурации обучения.

## 6. Конфигурация обучения NAFNet

Файл: `NAFNet/options/train/Tanahen/train_NAFNet_JPEG.yml`

### 6.1 Основные секции конфига

```yaml
name: NAFNet-JPEG-4070Ti          # название эксперимента
model_type: ImageRestorationModel # тип задачи
num_gpu: 1                        # используем одну RTX 4070 Ti
manual_seed: 42                   # для воспроизводимости
```

**Пути к данным** (можно относительные, от папки `NAFNet`):

```yaml
datasets:
  train:
    dataroot_gt: ../dataset_ready/train/hq_targets
    dataroot_lq: ../dataset_ready/train/lq_inputs
    gt_size: 256                  # нарезаем изображения на патчи 256×256
    batch_size_per_gpu: 8         # 8 патчей за один шаг
    use_flip: true                # аугментация – отражение
    use_rot: true                 # аугментация – повороты
```

**Архитектура сети** (соответствует NAFNet):

```yaml
network_g:
  type: NAFNet
  width: 32
  enc_blk_nums: [2, 2, 4, 8]
  middle_blk_num: 12
  dec_blk_nums: [2, 2, 2, 2]
```

**Параметры обучения:**

```yaml
train:
  optim_g:
    type: AdamW
    lr: 1e-3
  total_iter: 200000              # 200 тысяч итераций
  scheduler:
    type: TrueCosineAnnealingLR   # плавное снижение learning rate
```

**Логирование и метрики:**

```yaml
logger:
  print_freq: 200                 # каждые 200 итераций вывод в консоль
  save_checkpoint_freq: 5000      # сохранять веса каждые 5000 итераций
  metrics:
    psnr: {type: calculate_psnr}
    ssim: {type: calculate_ssim}
```

> **Зачем эти метрики:** PSNR (пиковое отношение сигнал/шум) и SSIM (индекс структурного сходства) – стандартные объективные меры качества восстановления. Они будут автоматически вычисляться на тестовой выборке и логироваться.

## 7. Запуск обучения

В терминале VSCode (Ubuntu), находясь в папке `NAFNet`, выполнить:

```bash
python basicsr/train.py -opt options/train/Tanahen/train_NAFNet_JPEG.yml
```

**Что происходит после запуска:**

1. PyTorch инициализирует модель, загружает веса (если указан `pretrain_network_g`) или инициализирует случайно.
2. CUDA выделяет память на видеокарте (около 11 ГБ из 12 ГБ).
3. Начинается итеративный цикл:
   - Загружается батч из 8 изображений (пары LQ/HQ).
   - Модель делает предсказание (восстановленное изображение).
   - Вычисляется L1-потеря между предсказанием и HQ.
   - Градиент распространяется назад, веса обновляются.
   - Каждые 200 итераций в консоль выводится текущее значение loss, PSNR, SSIM на валидации.
   - Каждые 5000 итераций сохраняется чекпоинт модели (файл `.pth`).

**Мониторинг через VSCode:**

- Можно открыть второй терминал и выполнить `nvidia-smi` (хотя на WSL отображается неполно, но память и температура видны).
- Файлы весов появляются в `NAFNet/experiments/NAFNet-JPEG-4070Ti/models/`.
- Логи можно просматривать прямо в терминале VSCode.

## 8. Инференс (тестирование модели)

Скрипт `test_my_image.py` предназначен для применения обученной модели к любому изображению.

**Принцип работы:**

1. Загружает архитектуру NAFNet с теми же параметрами, что и в конфиге.
2. Загружает сохранённые веса (например, `net_g_latest.pth`).
3. Преобразует входное изображение в тензор, нормализует в диапазон [0,1].
4. Прогоняет через модель в режиме `eval()` (без вычисления градиентов).
5. Сохраняет результат как PNG.

**Важные фрагменты кода:**

```python
device = torch.device('cuda' if torch.cuda.is_available() else 'cpu')
model = NAFNet(img_channel=3, width=32, middle_blk_num=12, 
               enc_blk_nums=[2,2,4,8], dec_blk_nums=[2,2,2,2])
checkpoint = torch.load(MODEL_PATH, map_location=device)
model.load_state_dict(checkpoint['params'])
model.to(device).eval()
```

**Использование:**

1. Положите изображение (например, `my_shakal_photo.jpg`) в корень `Tanahen`.
2. Укажите путь к весам в переменной `MODEL_PATH`.
3. Запустите:
   ```bash
   python test_my_image.py
   ```
4. Результат `fixed_by_nafnet.png` появится в той же папке.

- `Ctrl + `` — открыть терминал. Он уже будет внутри WSL.

```json
{
    "terminal.integrated.profiles.linux": {
        "bash": {
            "path": "bash",
            "args": ["-c", "source ~/Projects/naf_env/bin/activate && exec bash"]
        }
    },
    "terminal.integrated.defaultProfile.linux": "bash"
}
```

### 9.3 Редактирование Python-скриптов и YAML

VSCode подсвечивает синтаксис, проверяет отступы, позволяет запускать выделенный код через `Shift+Enter`.

### 9.4 Отладка

- Установите расширение Python (от Microsoft).
- Поставьте брейкпоинты в `test_my_image.py`, нажмите `F5` и выберите `Python File`.
