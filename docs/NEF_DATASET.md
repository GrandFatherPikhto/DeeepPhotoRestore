# Обучение нейросети `NAFNet` на датасете из RAW-файлов (Nikon D600)

## 1. Подготовка датасета
### 1.1. Исходные данные
Исходные RAW-файлы формата NEF (Nikon D600) – 12 штук.

Требовалось получить пары «байеровский массив (LQ) → полноцветное RGB (HQ)».

### 1.2. Разработка скрипта prepare_dataset_raw.py

Создан скрипт, который:

Читает NEF-файлы с помощью библиотеки rawpy (в дальнейшем заменено на imageio для лучшей совместимости).

Извлекает эталонное RGB (HQ) методом raw.postprocess() (8 бит, цветовое пространство sRGB).

Извлекает сырой байеровский массив (одноканальный, 16 бит) из raw.raw_image.

Сохраняет HQ в виде PNG, LQ – в виде 16-битных TIFF (чтобы сохранить динамический диапазон).

Организует структуру папок train/hq_targets, train/lq_inputs, test/... с разбиением 95%/5%.

Добавляет аугментацию (повороты, отражения) для увеличения объёма данных (на практике у вас получилось ~11 обучающих пар).

Важно: В процессе отладки выяснилось, что rawpy с камерой Nikon D600 возвращает неполное изображение. Проблема решена переходом на imageio (более надёжный бэкенд).

### 1.3. Структура готового датасета
```text
dataset_ready/
  train/
    hq_targets/     # эталонные RGB (PNG)
    lq_inputs/      # байеровские массивы (TIFF, 16 бит)
  test/ ... аналогично
```  
## 2. Выбор и адаптация архитектуры NAFNet
### 2.1. Исходный репозиторий
Использован официальный репозиторий megvii-research/NAFNet.

NAFNet – современная архитектура для восстановления изображений (шумоподавление, деблур, супер-резолюция).

### 2.2. Проблема: NAFNet ожидает трёхканальный вход
Ваши LQ – одноканальные байеровские массивы.

В текущей версии NAFNet параметр входных каналов называется img_channel, но сеть не поддерживает num_in_ch=1 (в исходном коде сети нет возможности менять число входных каналов независимо от выходных).

Решение: на этапе загрузки данных преобразовывать одноканальный байер в трёхканальный путём дублирования канала:

```python
lq = np.concatenate([lq, lq, lq], axis=2)
```

В конфиге указано img_channel: 3. Такой трюк позволил использовать сеть «как есть».

## 3. Написание кастомного даталоадера
## 3.1. Требования BasicSR

BasicSR ожидает, что датасет возвращает словарь с ключами 'lq' и 'gt' (тензоры формата C×H×W).

Даталоадер должен быть унаследован от torch.utils.data.Dataset.

## 3.2. Создание класса RawDataset (файл my_basicsr/data/raw_dataset.py)

В __init__ считывает пары (.tiff и соответствующий .png) из папок lq_inputs и hq_targets.

Учитывает, что имена LQ содержат суффикс _bayer, а HQ – нет (удаление суффикса при поиске пары).

В __getitem__:

Загружает HQ через cv2.imread, нормализует в [0,1].

Загружает LQ через tifffile.imread (16 бит), нормализует в [0,1].

Дублирует одноканальный LQ в три канала.

Приводит изображения к одинаковому размеру (обрезка по минимальным размерам).

Выполняет случайный кроп (gt_size) и аугментации (flip, rotate), если задано в конфиге.

Возвращает тензоры (C,H,W).

### 3.3. Интеграция в BasicSR без изменения исходного кода
Проблема: BasicSR ищет классы датасетов в модулях, перечисленных в _dataset_modules.

Решение: в скрипте запуска run_training_register.py динамически добавляем ваш модуль в basicsr.data._dataset_modules:

```python
import basicsr.data
import my_basicsr.data.raw_dataset as raw_ds
basicsr.data._dataset_modules.append(raw_ds)
```

После этого в YAML-конфиге можно указывать type: RawDataset (без префиксов).

## 4. Настройка конфигурационного файла YAML
### 4.1. Основные секции

name, model_type: ImageRestorationModel, num_gpu: 1, manual_seed.

path (пути к экспериментам, чекпоинтам, логам).

datasets.train и datasets.val с параметрами:

type: RawDataset

dataroot_gt, dataroot_lq

gt_size: 256, use_hflip, use_rot

batch_size_per_gpu: 4, num_worker_per_gpu: 4

network_g:

type: NAFNet

img_channel: 3, width: 32, остальные параметры по умолчанию.

train:

optim_g: AdamW, lr: 0.001

scheduler: TrueCosineAnnealingLR

total_iter: 200000 (впоследствии уменьшено для теста)

pixel_opt: L1Loss

logger: print_freq: 10, save_checkpoint_freq: 5000, метрики PSNR, SSIM.

### 4.2. Устранение типовых ошибок
YAML-парсер воспринимал 1e-3 как строку → использовано !!float 1e-3 или просто 0.001.

dataset_enlarge_ratio должен быть в секции datasets.train, а не train.

## 5. Создание скрипта запуска run_training_register.py
Финальный скрипт выполняет следующие действия:

Добавляет пути к проекту и к NAFNet в sys.path.

Импортирует ваш даталоадер.

Регистрирует его через добавление в basicsr.data._dataset_modules.

Запускает basicsr.train.main() с подменой sys.argv.

## Запуск:

```bash
python run_training_register.py -opt options/train/train_NAFNet_RAW_4070Ti.yml
```

## 6. Результаты первого запуска
Обучение стартовало, loss начал снижаться (с ~0.288 до ~0.23 за первые итерации).

GPU (RTX 4070 Ti) загружен, память используется (~6 ГБ).

Оценочное время полного цикла (200k итераций) – несколько дней, что ожидаемо для 11 изображений и неоптимальных параметров.

Параметр dataset_enlarge_ratio в текущей конфигурации не применился (баг BasicSR), но это не влияет на работоспособность.

## 7. Рекомендации по дальнейшей работе
Увеличить датасет – 11 файлов недостаточно. Использовать публичные датасеты (Zurich RAW to RGB, SR‑RAW) или добавить собственные снимки.

Применить предобученные веса (например, NAFNet-SIDD) для ускорения сходимости.

Уменьшить total_iter до 5000–10000 для быстрого тестирования и отладки.

Написать скрипт инференса для применения обученной модели к произвольному байеровскому TIFF и визуального сравнения с исходным RGB.

Этот план и реализация позволяют вам в дальнейшем экспериментировать с архитектурами, датасетами и гиперпараметрами, не изменяя код NAFNet и сохраняя воспроизводимость. Все созданные скрипты и конфиги находятся в вашем проекте и готовы к использованию.
